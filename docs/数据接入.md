# 数据接入与按日归档

当前已接入「采购入库」`procurement-inbound`。接口说明统一维护在 [入库记录接口](入库记录接口.md)，
调用、清洗和归档由代码实现，不使用 JSON 描述接口协议。

## 目录与时间

```text
data/
  raw/
    procurement-inbound/
      2026/
        2026-10/
          2026-10-25/data.parquet
          2026-10-26/data.parquet
  processed/
    procurement-inbound/
      2026/
        2026-10/
          2026-10-25/data.parquet
          2026-10-26/data.parquet
```

路径统一为 `data/<层>/<来源>/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet`。

- **归档日**：按上海时区计算的抓取日期，表示当天抓到的一版完整数据。
- **抓取时间**：表内 `_fetched_at`，精确到秒；`_source` 标记来源。
- **业务日期**：记录中的入库日期、调价生效日期等，用于计算实际覆盖范围。

这些日期不互相代替。10 月 25 日抓取的文件可以包含多个月的入库记录。
每天单独保留，跨日不覆盖；同日重复同步原子替换当天文件，历史日期保持不变。
分析一次只读取一版，不能拼接每日全量快照，否则会重复计数。
接口当前没有按日期查询的参数，抓取日归档也不表示请求了当天的增量。

## raw 和 processed

- `raw` 保留接口返回的列名、值、类型和单位，只添加两列来源元数据。
- `processed` 在对应日生成：改列名、转数值、金额由元转万元、派生年月，保留未知字段和原始抓取时间。
- 报告写入 `outputs/reports/<抓取日>/`，包含输入归档路径、归档日、抓取时间和业务覆盖范围。

历史留存的是当时的数据版本。代码口径变化后复核旧报告，也需要使用当时的代码版本及运行参数。

## 同步与抽查

先按 [项目入口](../README.md) 安装项目、配置 `.env`，再执行：

```bash
python scripts/sync_data.py --source procurement-inbound
python scripts/sync_data.py --dry-run  # 拉取并验证清洗，不写文件
python scripts/sync_data.py --list     # 列出两层的归档日期，不联网、不写文件

python -m connectors.procurement_inbound --show-config
python -m connectors.procurement_inbound --check-env  # 会真打一页
python -m connectors.procurement_inbound --self-test  # 离线自测

python scripts/peek_api.py --days 3
python scripts/peek_api.py --from-file /tmp/resp.json --pt 2026-10-25
```

兼容来源别名 `采购入库`、`入库明细`。空响应或清洗校验失败时不写归档；单个文件先写临时文件再替换。
raw 写入成功而 processed 写入失败时，下一次读取会从同日 raw 重建底表。

## 分析读取

```python
from pipeline import load_source

# 默认读取最新归档
frame, meta = load_source("procurement-inbound")

# 精确读取指定日；缺失时直接报错，不使用其他日期冒充
frame, meta = load_source("procurement-inbound", snapshot_date="2026-10-25")

# 选列不影响完整来源元数据
frame, meta = load_source(columns=["物料编码", "数量合计"])
```

`meta` 包含 `source`、`snapshot_date`、`data_file`、`rows`、`fetched_at`、`data_month_range`。
默认最新日期从 raw 和 processed 两层共同确定；新 raw 尚未清洗时，自动生成该日底表，不回退到旧日数据。

修改清洗代码后，可以用归档 raw 重新生成指定日底表，不重新调用接口：

```python
from pipeline import prepare_source

prepare_source("procurement-inbound", snapshot_date="2026-10-25")
```

直接检查原始记录或读取其他来源的归档：

```python
from data import read_snapshot

raw, meta = read_snapshot("raw", "procurement-inbound", "2026-10-25")
```

实时分析而不落盘可使用 `pipeline.load_from_connector()` 或分析命令的 `--read-from connector`；
实时取数执行相同清洗，不能同时指定历史 `--snapshot-date`。

## 新增来源：采购价格调整单

新来源到位后增加对应文件，不预先编造接口地址和字段：

1. `docs/采购价格调整单接口.md`：维护接口约定和字段含义。
2. `src/connectors/price_adjustment.py`：实现接口调用、认证和分页，返回原始记录。
3. `src/cleaning/price_adjustment.py`：按文档清洗字段、类型和单位，并计算该来源的业务日期覆盖范围。
4. 在 `src/pipeline.py` 的 `SOURCE_HANDLERS` 增加该来源的客户端、清洗和覆盖范围函数。
5. `notebooks/采购价格调整分析.ipynb`：开始探索，稳定后的计算提取到 `src/`，批量入口放 `scripts/`。

底层 `data.py` 不限制来源为采购入库，无需修改归档规则。调价单届时沿用：

```text
data/raw/price-adjustment/2026/2026-10/2026-10-25/data.parquet
data/processed/price-adjustment/2026/2026-10/2026-10-25/data.parquet
```

调价单和入库数据联合分析时，分别明确选择两者的归档日期，不假定它们当天都已成功同步。
共享的认证、传输逻辑等到确实相同时再抽取。

## 凭证与备用资料库

`.env` 或环境变量提供 `SCM_API_APP_KEY`、`SCM_API_APP_SECRET`；可选设置接口主机、代理和超时，
见 [.env.example](../.env.example)。环境变量优先，凭证不进入代码或文档。

旧 WorkBuddy 月度导出可手动下载，接口失败时不会自动更换来源：

```bash
python -m connectors.library_parquet --list
python -m connectors.library_parquet --fetch 入库明细
```

该导出已有中文列名和万元单位，可以读取分析，但不能当成接口 raw 再执行单位换算。
缓存位于 `~/.cache/scm-ana/library/`，不会与正式接口归档混放。
