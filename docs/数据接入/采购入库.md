# 采购入库：归档与清洗方案

本文件是「采购入库」这一路数据源的接入方案：上游文件怎么来、raw 怎么归档、清洗怎么做、
代码放在哪。新增其他数据源时照这个结构各写一份，放在 `docs/数据接入/<来源名>.md`。

- 来源 id：`procurement-inbound`（别名：采购入库、入库明细）
- 对应代码：`src/sources/procurement_inbound.py`、`src/pipeline.py`、`src/archive.py`
- 归档目录：`data/raw/procurement-inbound/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet`

上游不再提供数据中台接口，改为把导出文件放到项目根目录的 `.local-data/`，本地脚本读取后原样归档。
raw 阶段不做字段改名、单位换算和任何格式转换；清洗由业务侧单独完成。

## 一、来源文件

- 目录：项目根目录 `.local-data/`，不进版本库（见 `.gitignore`）。可用环境变量
  `SCM_ANA_LOCAL_DATA_DIR` 指向别处。
- 文件名匹配 `入库明细*.xlsx`（带空格也匹配）。读取 `入库明细（含单价）` 工作表，文件没有同名表时取第一个表。
- 多个文件按文件名排序合并，每个文件一份独立表头。
- 列名、取值和单位以导出文件为准，代码不猜测缺失字段，也不补默认值。

当前上游文件：

| 文件 | 覆盖业务区间 | 行数 |
| --- | --- | --- |
| 入库明细（2025）.xlsx | 2025-01-01 ~ 2025-12-31 | 333,693 |
| 入库明细（2026）.xlsx | 2026-01-01 ~ 2026-09-30 | 271,169 |

导出文件的字段口径：中文列名，金额单位已是万元；含 `出入库日期` 日粒度、`数量`、`采购金额(万)`、
`采购不含税金额(万)`、`供应商名称` 等列；不含供应商编码、供应商类型等属性列。
上游导出已按板块（检验、检验产品、诊断）、分析类型（入库）、非内部交易过滤。

## 二、归档规则

路径统一为 `data/<层>/<来源>/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet`，所有来源通用。

表内两列元数据：`_source` 标记来源，`_fetched_at` 记录转换时间（上海时区，精确到秒）。

### 分档方式

| 方式 | 目录日期含义 | 什么时候用 |
| --- | --- | --- |
| `fetch-day` | 转换当天，一版全量快照 | 看「这一版数据长什么样」，默认 |
| `business-date` | 记录里的业务日期（`出入库日期`） | 看某个业务日的数据，或按日对比版本 |

两种方式都用同一套路径规则，`data/processed/` 同理。

- `fetch-day`：每次转换存一版全量。跨日不覆盖，同日重复转换原子替换当天文件。
- `business-date`：按 `出入库日期` 逐日成档，593 个有记录的日期各存一份，可用 `--dates` 只挑某几天。
  这种方式下目录日期是业务日期，与表内 `_fetched_at`（转换时间）本就不相等，归档时不做一致性校验。

按日归档时，一次分析只读一版，不能拼接多份每日快照，否则会重复计数。

### raw 与 processed

- `raw`：导出文件的**直接转换**，列名、取值、类型和单位全部原样，只追加两列来源元数据。
- `processed`：业务侧清洗后的底表，写在同一套路径下。`pipeline.load_source()` 优先读 processed，
  没有底表时直接读 raw。

上游两份文件合并后，`仓库编码`、`货号`、`批次号` 这类「一份是数字、一份是文本」的列统一成文本，
数值不变（前导零也保住）。这是合并两文件的必然结果，不是数据改动。

## 三、清洗方案

清洗在业务侧完成，本仓库不内置转换规则，只提供归档位置和读取入口。

业务侧把清洗结果写到 `data/processed/procurement-inbound/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet`，
沿用同一套路径规则和两列元数据约定（`_source`、`_fetched_at`）。

分析侧只做**字段名映射**，不改数值、不做单位换算（`src/analysis/procurement_increment.py` 的
`normalize_columns`）：

| 导出文件列名 | 分析口径列名 |
| --- | --- |
| 数量 | 数量合计 |
| 年份 | 采购入库年份 |
| 月份 | 采购入库月份 |

已经用清洗后的列名（数量合计、采购入库年份、采购入库月份）时保持原样，两套命名都能直接跑。

## 四、执行

```bash
python scripts/sync_data.py --source procurement-inbound                        # 转换当天一版全量
python scripts/sync_data.py --source procurement-inbound --mode business-date   # 按业务日期逐日成档
python scripts/sync_data.py --source procurement-inbound --mode business-date \
    --dates 2026-09-30,2026-09-29                                             # 只归档指定日期
python scripts/sync_data.py --dry-run                                         # 读取并校验，不写文件
python scripts/sync_data.py --list                                            # 列出归档日期

python -m sources.local_excel --read                                          # 只看本地文件和行数
```

读取归档：

```python
from pipeline import load_source

frame, meta = load_source("procurement-inbound")                    # 最新一版
frame, meta = load_source("procurement-inbound", snapshot_date="2026-09-30")
frame, meta = load_source(columns=["物料编码", "数量"])              # 选列不影响元数据
```

`meta` 包含 `source`、`snapshot_date`、`layer`、`data_file`、`rows`、`fetched_at`、`data_month_range`。
实时读取而不落盘用 `pipeline.load_from_source()` 或分析命令的 `--read-from live`。

## 六、新增数据源

照这份文档的结构做四件事：

1. `docs/数据接入/<来源名>.md`：写来源文件约定、字段口径、归档与清洗方案；
2. `src/sources/<来源名>.py`：实现读取（可复用 `LocalExcelSource`），声明来源 id、别名、业务日期列；
3. `src/sources/__init__.py`：在 `REGISTRY` 注册；
4. `src/pipeline.py`：无需改动——注册后 `sync_data.py --source <来源名>` 直接可用。

归档规则、路径结构和 `data/processed/` 约定对所有来源一致，不因新增来源而变。

## 七、备用资料库

WorkBuddy 资料库里的 parquet 可手动下载，作为补充材料：

```bash
python -m sources.library_parquet --list
python -m sources.library_parquet --fetch 入库明细
```

该导出已有中文列名和万元单位，可以读取分析。缓存位于 `~/.cache/scm-ana/library/`，
不会与正式归档混放。
