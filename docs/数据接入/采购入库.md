# 采购入库：接入与清洗方案

本文件是「采购入库」这一路数据源的接入与清洗方案，八节固定结构，遵循
`.workbuddy/skills/data-cleaning` 的方法论。新增其他来源时复制
`.workbuddy/skills/data-cleaning/templates/来源文档.md` 各写一份，放在 `docs/数据接入/<来源名>.md`。

- 来源 id：`procurement-inbound`（别名：采购入库、入库明细）
- 对应代码：`src/sources/procurement_inbound.py`（口径、取数、导入）、`src/read_data.py`（取数门面）、
  `src/archive.py`（归档存储）
- 归档目录：`data/raw/procurement-inbound/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet`

## 一、来源与接入

### 1.1 来源形态

上游不提供接口，只给**导出文件**。约定写成「换批次也不失效」的形式：

- **落盘位置**：项目根目录 `.local-data/`，不进版本库（见 `.gitignore`）；换机器或放别处时用环境变量
  `SCM_ANA_LOCAL_DATA_DIR` 指向目标目录。
- **文件发现**：按 `入库明细*.xlsx` 匹配（文件名中间带空格也匹配），不依赖文件名里的年份或日期。
  业务日期一律取记录内的 `出入库日期`，不从文件名推断。
- **工作表选择**：优先读名为 `入库明细（含单价）` 的工作表；没有同名表时取第一个工作表。
  一份文件只读一个工作表，不跨表拼接。
- **多文件合并**：按文件名排序依次读入，每个文件各自一份表头；一份文件覆盖一段连续业务区间，
  文件之间不重叠。
- **字段口径**：列名、取值、类型和单位一律以导出文件为准。代码不猜缺失字段、不补默认值、不重排列序。

导出文件本身的形态约定（不随批次变化）：

- 中文列名，一行一条出入库明细；金额单位已是万元，单价单位是元。
- 必有 `出入库日期`（日粒度），作为归档成档依据。
- 上游已按板块（检验、检验产品、诊断）、分析类型（入库）、非内部交易做过过滤，
  因此 raw 里只会出现这三类板块和「入库」一种分析类型。
- 不含供应商编码、供应商类型等属性列；供应商只有名称，没有主数据 ID。

具体批次的文件名、覆盖区间、行数属于数据快照，不写进本文档，用命令查：

```bash
uv run python scripts/sync_data.py --list          # 已归档的日期
```

```python
from read_data import archive_overview
archive_overview()    # 每个日档的层、行数、文件大小、首末日档
```

### 1.2 归档规则

**一天一个 parquet 文件**，目录用记录里的业务日期（`出入库日期`）：

```text
data/raw/procurement-inbound/
  2025/2025-01/2025-01-02/data.parquet
  2026/2026-09/2026-09-30/data.parquet
```

路径规则 `data/<层>/<来源>/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet` 对所有来源通用。

- **归档日** = 记录里的业务日期；**转换时间** = `_fetched_at`（上海时区，精确到秒）；`_source` 标记来源。
- 没有 `出入库日期` 的行直接跳过，不落文件。
- 同一业务日重复归档原子替换当天文件，历史日期不受影响。

截至 2026-10-30 的归档状态：业务区间 2025-01-01 ~ 2026-09-30，638 天里有记录的有 **593 天**，
45 天无记录（春节和长假），合计 604,862 行。这是时点快照，新批次后以 `archive_overview()` 为准。

### 1.3 分层

- `raw`：来源文件的**直接转换**，列名、取值、类型、单位全部原样，只追加两列元数据。
- `processed`：清洗后的底表，写在同一套路径下。读取时逐日挑层：当天有 processed 就用 processed，
  没有退回 raw（`sources.procurement_inbound.preferred_layer`），因此可以只重做部分日期。

两份上游文件合并后，`仓库编码`、`货号`、`批次号` 这类「一份是数字、一份是文本」的列统一成文本，
数值不变（前导零保住）。这是合并的必然结果，不是数据改动。

### 1.4 历史迁移

原来放在 raw、实际已清洗过的文件，按 `_fetched_at` 迁入
`data/processed/procurement-inbound/2026/2026-10/2026-10-28/data.parquet`，内容不变。
现存底表没有对应原始记录，不反向生成 raw；下一次成功归档会生成当天的 raw 日档。

## 四、口径差异

同一个业务概念，两个来源系统（ebs / nc）的表达方式不同。**这五条是本源的清洗风险点，改规则前先看这一节。**

| # | 概念 | ebs 的表现 | nc 的表现 | 证据 | 处理 |
| --- | --- | --- | --- | --- | --- |
| 1 | 退货单价放哪列 | 只有 `购退单价`，`采购单价` 全为 0 | 只有 `采购单价`，`购退单价` 全为 0 | 退货 90 行 vs 70 行，两列互斥 | 合并成一列，见 5.2 |
| 2 | 入库/退货的叫法 | PO接收 / 退回供应商 | 普通采购入库 / 采购退货 | 4 种取值与系统 1:1 | 整列丢弃，用 `数量 < 0` 判定 |
| 3 | 采购类型是否带「合同」 | 定向采购 | 定向采购合同 | 「合同」后缀与系统 1:1 | 去后缀归并为 4 类 |
| 4 | 单据编码格式 | `3070005745 - 3`（数字 + 空格 + 行号） | `CR2001260900358` | ebs 21,452 行全含「 - 」，nc 全以 CR 开头 | 拆主单号 + 行号只对 ebs 做（待确认） |
| 5 | 缺值写法 | 用空 | 用 0 | `购退单价` 空 90 行，`购退不含税单价` 全非空但 68 行填 0 | 统一为 null |

## 五、清洗规则

清洗产物写 `data/processed/procurement-inbound/`，规则必须可复现。处置分五种：
保留 / 规范化 / 归并 / 标记 / 丢弃（挂起项见第八节）。

### 5.1 规范化

| 处理 | 字段 | 说明 |
| --- | --- | --- |
| str → datetime | 出入库日期 | 同时校验 `年份`/`月份` 与日期一致 |
| int64 → str | 公司编码、物料编码 | 编码是标识，转文本防止误参与运算和前导零丢失 |
| 去空格 + 拆行号 | 单据编码 | ebs 侧 `3070005745 - 3` → 主单号 + 行号（待确认，见第八节） |
| 全角转半角 | 公司名称（39 行） | 仅全角字母数字；中文括号保留 |

### 5.2 归并

**退货单价合并成一列。** 两个系统放在不同列，不合并则按列聚合各丢一半，
且 ebs 的 `单价 × 数量 ≠ 金额`。

| 系统 | 退货行（数量<0） | `采购单价` 非零 | `购退单价` 非零 | 单价 × 数量 对上金额 |
| --- | --- | --- | --- | --- |
| ebs | 90 | **0** | 89 | 用 `购退单价`：90/90 |
| nc | 70 | 67 | **0** | 用 `采购单价`：70/70 |

规则：`数量 < 0` 且 `数据来源系统 == "ebs"` 且 `购退单价` 非空 → 用 `购退单价` 覆盖 `采购单价`；
`采购不含税单价` 同理由 `购退不含税单价` 覆盖。`购退单价`、`购退不含税单价` 合并后不再保留。

**采购类型名称（8 → 4）**：去掉「合同」后缀。**不要**再拆「是否签合同」这一维度——
它等价于数据来源系统（见第四节第 3 条），拆出来是假信息。

| 原值 | 归并后 |
| --- | --- |
| 定向采购、定向采购合同 | 定向采购 |
| 指定采购、指定采购合同 | 指定采购 |
| 集中采购、集中采购合同 | 集中采购 |
| 自行采购、自行采购合同 | 自行采购 |
| 空（220 行） | 未知 |

**财务内部外供应商类型**：内部关联单位 → 内部；外部单位、外部关联单位 → 外部；空 → 未知。

**自定义内外部供应商**：已是两值，**不参与上面的归并**。两个口径不同，都保留：
自定义口径内部 1,704 行，财务口径内部关联 10,354 行，差 8,650 行。

**产品类型（4 → 3）**：`科研产品2`（4 行）→ `科研产品`。

**主单位**：`arr`（4 行）→ 空。其余 29 个是合法单位，单位之间不换算（盒/箱不可互换）。

**仓库类型**：空 4 行 → 未知。

**税率**：0.13 / 0.01 / 0.03 / 0.0 → 13% / 1% / 3% / 0%，作为枚举校验，不做四舍五入。

**物料分类**：

1. 三级分类：`其他`(4)、`其他化学品`(5)、`其他办公设备`(5)、`其他消耗品`(110) 语义不同，
   底表保留原值，只在报表层合并为「其他类」。
2. 四级分类：`无分类` → 空；7 个跨父类的值以行数最多的父类为准，并输出对照表交业务确认。
3. 五级分类：按 `三级分类` 是否为 检测设备 / 辅助设备 / 计量器具 / 备品备件 判定设备类，
   其余判为方法类，拆成 `检测方法` 与 `设备类别` 两列；`无分类`(3,765 行) → 空。

### 5.3 标记

异常值是真实业务时不删，只加布尔列：

| 标记列 | 条件 | 规模（2026-09） |
| --- | --- | --- |
| `是否退货` | `数量 < 0` | 160 行 |
| 单价异常 | `采购单价 <= 0` | 4,655 行（赠品、样品、未计价） |
| 金额异常 | `采购金额(万) <= 0` | 4,722 行 |

误判成倒挂，按绝对值比是 0 行。

## 六、断言校验

每次清洗后必跑，两条都要通过。写法见 `.workbuddy/skills/data-cleaning/templates/断言清单.md`。

| 断言 | 表达式 | 当前实测 |
| --- | --- | --- |
| 金额勾稽 | `采购单价 × 数量 / 10000 ≈ 采购金额(万)`，容差 0.01 | 41,849 / 41,849 = 100% |
| 行数守恒 | 除显式去重外，清洗前后行数相等 | 相等（去重为挂起项） |
| 值域 | `是否退货` 由数量符号决定；税率 ∈ {0.13, 0.01, 0.03, 0.0} | 通过 |

```python
calc = clean["采购单价"].fillna(0) * clean["数量"].fillna(0) / 10000
ok = (calc - clean["采购金额(万)"].fillna(0)).abs().le(0.01)
assert ok.all(), f"勾稽失败 {len(clean) - ok.sum()} 行"
```

对照组：合并前 ebs 退货行因为 `采购单价` 全为 0，只有 7 行碰巧成立；合并后 100%。
