# 采购降本自动化核算方案

**版本：第一阶段业务方案｜2026年10月28日**

## 一、建设目标与核算范围

基于采购价格调整单、钉钉多维表及ERP实际入库数据，建立自动化采购降本核算流程，实现数据获取、价格匹配、降本计算、业务复核、标准化处理与统一汇总。

第一阶段分为两条计算路径：

| 核算类型 | 处理方式 | 是否计入总降本 |
|---|---|---|
| 直接涨跌 | 根据采购价格调整单自动计算 | 是 |
| 渠道替换 | 人工填报基础信息，系统计算 | 是 |
| 品牌替换 | 人工填报基础信息及单位换算关系，系统计算 | 是 |
| 规格替换 | 人工填报基础信息及单位换算关系，系统计算 | 是 |
| 税率调整 | 独立表格人工填报 | 否，仅展示 |
| 返利 | 独立表格人工填报 | 否，仅展示 |

**年度总降本 = 直接涨跌 + 渠道替换 + 品牌替换 + 规格替换**

各类型降本再根据核算年度分别归集为新增和存量。

## 二、数据来源与处理职责

### 2.1 ERP入库数据

ERP入库明细包含七个业务字段：

| 字段 | 作用 |
|---|---|
| 采购主体 | 确定降本适用公司 |
| 供应商 | 匹配采购关系 |
| 物料 | 匹配采购物料 |
| 单价 | 实际入库含税单价 |
| 税率 | 实际执行税率 |
| 数量 | 实际入库数量 |
| 日期 | 判断核算周期及月份 |

ERP单价与调价单价格统一采用含税口径。

第一阶段不依赖采购合同号、价格协议号等额外业务字段。

### 2.2 采购价格调整单

由工作流同步到钉钉多维表，核心信息包括：

| 字段 | 用途 |
|---|---|
| 调价单号、明细标识 | 定位调价记录 |
| 供应商、物料 | 匹配ERP入库 |
| 原含税价、现含税价 | 确定本次降本价差 |
| 价格生效日期 | 推算12个月核算周期 |
| 适用采购主体 | 采购员复核确认 |
| 前次调价关联 | 程序识别，存在歧义时人工确认 |

采购价格调整单属于集团统一定价，一条明细可以适用于多个采购主体。

实际核算时按采购主体分别归集，最终汇总集团降本金额。

### 2.3 替换涨跌人工填报

渠道、品牌、规格替换统一使用钉钉多维表填报。

| 字段 | 渠道替换 | 品牌/规格替换 |
|---|---|---|
| 替换类型 | 必填 | 必填 |
| 适用采购主体 | 必填 | 必填 |
| 原供应商、新供应商 | 必填 | 按业务填写 |
| 原物料、新物料 | 同物料编码 | 必填 |
| 原含税价、现含税价 | 必填 | 必填 |
| 价格生效日期 | 必填 | 必填 |
| 原、新计价单位 | 相同 | 必填 |
| 可比单位及换算系数 | 不需要 | 必填 |
| 业务依据 | 必填 | 必填 |
| 业务复核状态 | 必填 | 必填 |

采购员不需要每月填写实际入库数量。系统根据已确认的替换关系从ERP获取数量。

### 2.4 税率调整与返利

分别建立独立填报表，业务填写相关数据或确认金额。

第一阶段仅进行基础字段校验、数据归集与展示，不纳入总降本，也不开发自动协议返利核算。

## 三、统一核算周期与归属规则

### 3.1 核算周期

直接涨跌及三类替换涨跌统一使用价格生效日期推算核算周期。

**每条降本明细独立核算连续12个自然月。**

| 价格生效日期 | 核算开始 | 核算结束 |
|---|---|---|
| 2026-03-01 | 2026-03-01 | 2027-02-28 |
| 2026-06-15 | 2026-07-01 | 2027-06-30 |
| 2026-10-16 | 2026-11-01 | 2027-10-31 |
| 2026-12-20 | 2027-01-01 | 2027-12-31 |

规则：价格生效日为当月1日，从当月1日起算；其他日期从次月1日起算。到期后，该明细停止核算。

即使期间再次调整价格，前次明细的周期也不重启。

### 3.2 新增与存量

最终只保留两个汇总维度。

| 维度 | 核算口径 |
|---|---|
| 新增 | 调价或替换开始核算的当年度产生的降本贡献 |
| 存量 | 跨自然年度后、原12个月周期内继续产生的降本贡献 |

同自然年度连续调价，各次贡献均计新增。次年1月1日起，仍在有效期内的贡献转为存量。

原业务使用的“滚动存量”主要体现连续调价后前次贡献的延续计算，不再设立独立的第三个汇总维度。

说明：以**核算开始年度**作为新增认定年度是当前方案的统一实现口径；若价格生效日期在年末、核算从次年1月开始，这一边界仍需业务最终确认。

## 四、直接涨跌自动核算

### 4.1 核算公式

**单位降本 = 本次原含税价－本次现含税价**

**降本金额 = 单位降本 × 符合条件的实际入库数量**

每次调价只计算自身产生的固定增量价差。

### 4.2 入库匹配逻辑

系统按以下顺序处理：

1. 根据供应商、物料识别价格调整明细。
2. 根据价格前后关系、生效时间及主体适用范围自动识别连续调价历史。
3. 仅使用采购员确认适用范围内的ERP入库。
4. 根据入库单价匹配本次价格及同一调价历史中的后续价格。
5. 根据每条调价明细自身的12个月周期筛选入库。
6. 分别计算每条明细的固定增量降本。

当连续调价关系不唯一时，交由采购员在钉钉多维表复核。

不能简单使用“入库价低于调整后价格”作为匹配依据，因为不同采购主体或独立采购价格可能同时存在。

### 4.3 连续降价示例

假设：

| 调整单 | 调价 | 单位降本 | 核算周期 |
|---|---|---|---|
| T001 | 100→90 | 10元 | 2026.03—2027.02 |
| T002 | 90→80 | 10元 | 2026.06—2027.05 |

2026年7月按80元实际入库200件：

| 调整单 | 匹配数量 | 计算金额 | 归属 |
|---|---:|---:|---|
| T001 | 200 | 2,000元 | 新增 |
| T002 | 200 | 2,000元 | 新增 |
| 合计 | — | 4,000元 | 新增 |

2027年1月如果仍按80元入库200件，则两张调整单合计4,000元，全部归入存量。

2027年3月T001已到期，只保留T002的有效贡献。

**核心原则：同一笔入库可以支持多条尚未到期的调价明细，但每条明细只计算自己的增量价差。**

## 五、替换涨跌计算

### 5.1 渠道替换

渠道替换采用相同物料编码，新旧供应商可不同，无需进行单位换算。

**降本金额 =（原渠道含税价－新渠道含税价）× 新渠道ERP入库数量**

采购员确认新旧供应商关系、价格生效日期及适用主体；系统按照新供应商、新物料、实际执行价格和有效周期匹配入库。

### 5.2 品牌替换及规格替换

由采购员确认新旧物料关系与换算系数。

换算系数统一定义为：

**每个ERP采购计量单位对应的标准可比单位数量。**

计算公式：

原可比单位价 = 原含税单价 ÷ 原换算系数

新可比单位价 = 现含税单价 ÷ 新换算系数

实际可比数量 = ERP入库数量 × 新换算系数

**降本金额 =（原可比单位价－新可比单位价）× 实际可比数量**

例如：

| 项目 | 原品牌 | 新品牌 |
|---|---|---|
| 含税单价 | 100元/盒 | 45元/盒 |
| 规格 | 100测试/盒 | 50测试/盒 |
| 可比单位价 | 1元/测试 | 0.9元/测试 |

假设新品牌入库200盒：

实际数量 = 200 × 50 = 10,000测试

降本金额 = (1－0.9) × 10,000 = **1,000元**

品牌与规格替换的换算关系属于业务判断内容，必须经过人工复核，不能仅根据包装名称自动推断。

### 5.3 替换后再次直接降价

**已确认：替换降本与后续直接降价可以同时延续核算。**

例如先发生渠道替换，再发生直接降价：

| 明细 | 价格变化 | 单位贡献 |
|---|---|---:|
| R001 渠道替换 | 供应商甲100→供应商乙90 | 10元 |
| T002 直接降价 | 供应商乙90→80 | 10元 |

假设供应商乙按80元入库100件，且两条明细均在有效的12个月周期内：

| 降本来源 | 金额 |
|---|---:|
| R001替换降本 | 1,000元 |
| T002直接降本 | 1,000元 |
| 合计 | 2,000元 |

原替换降本继续按固定的10元差额计算，后续直接降价也只计算新增的10元差额。

品牌、规格替换后，如发生直接降价，也遵循固定贡献原则。替换部分使用可比单位计算，后续直接涨跌使用对应新物料的采购计价单位计算。

系统需要通过采购员确认的替换关系，将新供应商、新物料后续形成的调价明细连接起来。

## 六、人工复核与数据标准化

### 6.1 复核职责

| 环节 | 责任方 | 核心内容 |
|---|---|---|
| 基础信息填报 | 采购员 | 新旧关系、价格、单位、换算系数、生效日期 |
| 适用范围复核 | 采购员 | 确认适用采购主体 |
| 调价关系识别 | 脚本 | 自动识别历史调价及后续价格 |
| 歧义关系确认 | 采购员 | 确认无法唯一匹配的关系 |
| 数据标准化 | 脚本 | 统一字段、含税价格、可比单位、月份 |
| 金额核算与校验 | 脚本 | ERP数量匹配、公式计算、重复检查 |
| 结果确认 | 业务负责人 | 核对异常、确认正式汇总结果 |

### 6.2 程序校验

第一阶段重点执行以下校验：

| 校验项 | 具体要求 |
|---|---|
| 基础字段 | 价格、数量、日期及业务关系完整有效 |
| 主体范围 | 只使用已经确认的适用采购主体 |
| 单位换算 | 原、新可比单位一致，系数有效 |
| 调价关系 | 连续调价前后价格衔接正确 |
| 周期 | 入库日期在对应明细的有效12个月内 |
| 重复核算 | 同一入库记录对同一降本明细不得重复计算 |
| 归因 | 同一段价差不得同时被直接涨跌和替换涨跌重复归集 |

同一入库记录参与不同降本明细的有效增量贡献属于正常情况，不应被简单认定为重复数据。

### 6.3 异常处理

第一阶段只需要保留简洁的异常机制。

| 异常 | 处理办法 |
|---|---|
| 适用主体未确认 | 暂不纳入正式核算 |
| 调价历史存在歧义 | 交采购员复核关系 |
| 入库价格无法关联 | 输出待核对明细 |
| 单位换算缺失或异常 | 暂不计算对应替换明细 |
| 计算结果与业务依据冲突 | 标记异常，修正后重新计算 |

没有异常的数据正常计算；存在异常的部分单独列示，不阻断其他已确认记录。

## 七、统一计算与汇总

所有直接涨跌和替换涨跌计算结果，最终形成统一的标准核算明细。

### 7.1 标准核算明细

| 字段 | 含义 |
|---|---|
| 核算月份 | 降本归属月份 |
| 核算主体 | 实际采购公司 |
| 供应商、物料 | 当前执行采购关系 |
| 核算类型 | 直接、渠道、品牌、规格 |
| 来源明细 | 调价单明细或替换填报明细 |
| 价格生效日期 | 计算周期依据 |
| 核算开始、结束日期 | 独立12个月周期 |
| 标准单位降本 | 本次固定价差 |
| 实际核算数量 | ERP匹配数量或换算后数量 |
| 降本金额 | 系统计算结果 |
| 新增/存量 | 按自然年度归属 |
| 复核状态 | 判断是否进入正式汇总 |

系统同时保留原始ERP导入记录的来源位置、匹配依据和计算过程，便于核对，不要求ERP增加业务字段。

### 7.2 统一报表

| 降本类别 | 新增降本 | 存量降本 | 总降本 |
|---|---:|---:|---:|
| 直接涨跌 | 50,000 | 20,000 | 70,000 |
| 渠道替换 | 10,000 | 5,000 | 15,000 |
| 品牌替换 | 8,000 | 3,000 | 11,000 |
| 规格替换 | 6,000 | 2,000 | 8,000 |
| **合计** | **74,000** | **30,000** | **104,000** |

以上为示例金额。

税率调整、返利独立展示，不计入104,000元降本合计。

报表支持按核算月份、采购主体、供应商、物料、核算类型及新增/存量进行查询与汇总。

## 八、第一阶段实施流程

| 步骤 | 处理内容 | 输出 |
|---|---|---|
| 1. 数据同步 | 工作流同步调价单，采购员填报替换信息，获取ERP入库 | 原始数据 |
| 2. 业务确认 | 确认适用主体、替换关系及换算依据 | 可计算业务明细 |
| 3. 数据标准化 | 统一含税价格、数量单位和日期 | 标准化数据 |
| 4. 自动匹配 | 识别调价链、关联ERP入库、过滤12个月周期 | 匹配结果 |
| 5. 降本计算 | 固定增量价差计算，区分新增与存量 | 核算明细 |
| 6. 异常复核 | 检查缺失、歧义、重复归因等 | 已确认计算结果 |
| 7. 汇总输出 | 按月、年度及业务维度归集 | 降本报表 |

每个环节保留可查看的中间结果，方便逐步核对ERP匹配数量、单位价差与最终金额。

## 九、尚未最终确认的业务边界

以下事项不改变第一阶段核心计算框架，但需要在正式上线前确定。

| 优先级 | 问题 | 建议处理 |
|---|---|---|
| 高 | 12月生效、次年1月启动的降本归属年度 | 建议以核算开始年度作为新增年度 |
| 高 | 价格上涨或替换成本增加产生的负向金额 | 建议保留负数明细，确认是否冲减总降本 |
| 中 | 同一调整同时发生含税价与税率变化 | 建议复核归因，避免直接与税率展示金额重复解释 |
| 中 | ERP退货、红冲或历史补录 | 确认冲减或补算规则 |
| 中 | 价格、换算及金额的小数精度 | 统一计算精度和最终舍入规则 |
| 中 | 连续发生不同类型替换时的关联关系 | 优先人工确认，后续按需要扩展 |

第一阶段不扩展复杂合同关联、同价多协议识别及少见的价格碰撞模型。

## 十、第一阶段验收要求

重点验证以下典型业务场景：

| 测试场景 | 预期结果 |
|---|---|
| 单次直接降价 | 准确匹配主体、价格、日期及实际数量 |
| 同年度连续降价 | 前后调整分别计算固定差额，均归新增 |
| 跨年度延续 | 未到期贡献在次年归存量 |
| 多采购主体 | 只计算已确认适用范围内的入库 |
| 渠道替换 | 按新供应商、新物料实际入库计算 |
| 品牌、规格替换 | 按人工确认的换算关系计算可比数量 |
| 替换后再次降价 | 替换贡献与直接降价贡献分别延续，不重复计算价差 |
| 异常或未复核数据 | 不进入正式汇总，保留异常明细 |
| 税率调整、返利 | 独立展示，不影响总降本 |

**第一阶段验收目标：核算结果可计算、可复核、可追溯，并能通过ERP入库数据和业务填报依据复现。**
