2026-10-27 版）整理而来。取数实现见 [procurement_inbound.py](../src/connectors/procurement_inbound.py)，
字段清洗见 [清洗实现](../src/cleaning/procurement_inbound.py)。接口说明统一维护在本文件，不再另设 JSON 注册表。

### 3.1 派生字段

接口只给到「出入库日期」，分析口径要的年月由 `clean_procurement()` 派生：

| 目标列 | 来源 | 规则 |
| --- | --- | --- |
| `采购入库年份` | `inv_inout_date` | 取年份，如 `2026` |
| `采购入库月份` | `inv_inout_date` | 取月份，如 `9` |
| `出入库月份` | `inv_inout_date` | 当月 1 日，如 `2026-09-01` |

### 3.2 单位换算

接口金额单位是**元**（字符串，6 位小数），分析口径是**万元**。raw 保留元和原始类型，
`clean_procurement()` 转数值并乘 `0.0001` 后写入 processed，下游分析无需再次换算。
数量和税率也在此函数中转为数值；编码保留字符串。

## 六、认证

AK/SK 方式，请求头：

```
version: v1
appKey: {appKey}
timestamp: {调用时间戳}
signature: {md5(appSecret + timestamp)}
Content-Type: application/json
```

| 项 | 值 |
| --- | --- |
| 应用名 | workbuddy |
| appKey / appSecret | 见数据中台「授权信息」，**不写入仓库** |
| 凭证存放 | 项目根目录 `.env`（已 gitignore），或真实环境变量；**环境变量优先于 .env** |
| 变量名 | `SCM_API_APP_KEY` / `SCM_API_APP_SECRET` |
| 签名算法 | `md5(appSecret + timestamp)`，小写十六进制 |
| 时间戳 | 客户端按毫秒（13 位）生成，接口文档未写明单位，作为待确认项 |

调用示例（凭证取自 `.env`）：

```bash
set -a; . ./.env; set +a

TS=$(python3 -c 'import time;print(int(time.time()*1000))')
SIG=$(python3 -c "import hashlib,sys;print(hashlib.md5((sys.argv[1]+sys.argv[2]).encode()).hexdigest())" "$SCM_API_APP_SECRET" "$TS")

curl -s -X POST 'http://10.3.245.1:10073/easy-data-api/dazd_prod/workbuddy/ads_wkb_scm_inv_item_in_1d' \
  -H 'Content-Type: application/json' \
  -H 'version: v1' \
  -H "appKey: $SCM_API_APP_KEY" \
  -H "timestamp: $TS" \
  -H "signature: $SIG" \
  -d '{"page_num":"1","page_size":"200"}'
```

> 请求头名区分大小写：网关按 `appKey` 原样匹配，用 urllib 会自动发成 `Appkey`。
> 项目客户端因此走 `http.client`，见 `src/connectors/procurement_inbound.py`。

项目内取数：

```bash
python -m connectors.procurement_inbound --self-test     # 离线验证签名/翻页/解析
python -m connectors.procurement_inbound --show-config   # 看解析后的地址与凭证状态
python -m connectors.procurement_inbound --check-env     # 凭证 + 真打一页验签
python scripts/sync_data.py --source procurement-inbound --dry-run
```

按日期抽查（接口没有日期入参，只能翻页 + 本地筛，见下）：

## 七、凭证维护（.env）

### 为什么用 .env

appSecret 是凭据，不能进仓库；每次都 `export` 又太麻烦——换个终端或跑定时任务就丢了。
项目根目录的 `.env` 是本地私密文件，取数前由 `src/envfile.py` 自动载入：

```
scm-ana/
├── .env            # 本地私密，已 gitignore，同事之间不传
├── .env.example    # 模板，进仓库，给新同事照抄格式
└── src/envfile.py   # 读取器（标准库实现，无额外依赖）
```

优先级：**真实环境变量 > `.env`**。临时改一次值不必动文件：

```bash
SCM_API_APP_SECRET=xxx python scripts/sync_data.py --source 采购入库
```

### 首次配置

```bash
cp .env.example .env     # 已有 .env 就跳过
chmod 600 .env           # 只给自己读写
# 编辑 .env，填 SCM_API_APP_KEY / SCM_API_APP_SECRET
#（来源：数据中台「授权信息」表，应用 workbuddy）
python -m connectors.procurement_inbound --check-env
```

`--check-env` 会打印每个变量是否就绪、值从哪来（脱敏），再真打一页验证签名。

### 日常维护的四种情况

| 场景 | 做法 |
| --- | --- |
| 平台重置 / 轮换 appSecret | 改 `.env` 一行 → `--check-env` → 跑一次 `sync_data.py`；写入当天归档，不覆盖其他日期 |
| 临时用别人的账号调一次 | 命令行前置变量覆盖，不改文件 |
| 新同事入职 | 拉仓库 → `cp .env.example .env` → 找负责人要 appKey/appSecret（内部渠道，别贴群里） |
| 定时任务 | 不需要在 cron 里 export，脚本自己读 `.env`；`.env` 按脚本位置定位，不依赖 cwd |

### 安全红线

- `.env` 不进仓库、不进群、不截图。`.gitignore` 覆盖了 `.env` 与 `.env.*`，只放行 `.env.example`。
- 定期确认没被误提交：`git log --all -- .env` 应为空。一旦提交过，光删文件不够，**必须轮换密钥**。
- 权限保持 `600`，不要放进共享盘或资料库。

### 排错对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `缺少接口凭证` | `.env` 没填 / 变量名拼错 | `--check-env` 看哪个未就绪 |
| `code=3004 app key auth fail` | appSecret 不完整或错（文档里可能折成两段） | 重新完整复制，别漏后半段 |
| `接口连接失败 … Remote end closed` | 不在内网 / VPN，或网关拒了请求头 | 用 `curl` 打同一地址确认是网络侧还是客户端侧 |
| `code=0` 但结果为空 | 分页参数被忽略，或底层表已清空 | `python scripts/sync_data.py --list --source procurement-inbound` 核对行数与覆盖范围 |

## 八、与旧版导出数据的口径差异

旧导出（资料库月度汇总，39 列）已按月汇总；本接口是**日粒度明细**，粒度更细、字段更多，
落到分析脚本前需注意：

| 差异 | 说明 | 处理 |
| --- | --- | --- |
| 粒度 | 接口按「日期 × 物料 × 公司 × 仓库」出数，旧导出已按月汇总 | 下游按 `采购入库年月` 聚合，结果口径不变 |
| 金额单位 | 接口为元，旧导出为万元 | `clean_procurement()` 在 processed 中换算 |
| 只增字段 | 客户编码/名称、一级/二级存货分类、业务模式、多组织名称、分区日期 | 原样保留，供后续分析扩展 |
| 缺失字段 | `是否期间内新冠试剂`、`财务不含税成本金额(万)`、`十大渠道公司` 接口未提供 | 下游脚本用列存在性判断，缺列自动跳过；需要时再找数据中台补 |

### 待业务确认

1. `supplier_nature_merged`（供应商性质合并）是否等同旧导出的「供应商类型（财务）」。
2. `company_group_name`（多组织名称）与原「十大渠道公司」是否同一维度。
3. 时间戳单位（毫秒/秒）—— 当前按毫秒，若接口报签名过期再改客户端 `_now_stamp()`。
4. 入库数量为 0 的记录在样例中大量出现（`inv_in_qty = 0.000000`），是否属正常业务；
   若为无效行，需在取数或清洗阶段过滤，避免影响「连续采购」判定。
5. `pt`（分区日期）是**快照日**还是**业务日**。样例里 `pt=2026-10-26` 的记录
   `inv_inout_date=2024-03-01`，看着像整表快照日；若是，则「取某天业务数据」只能按
   `inv_inout_date` 筛，且每次抓取都要翻完全表（接口无日期入参、也不返回总条数）。
