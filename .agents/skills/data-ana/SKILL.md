# data-ana

一个场景 = 一份方案文档 + 一组确认 notebook + 一套稳定脚本 + 一个看板。
场景状态在 `notebooks/<场景>/分析方案.md`，头部记「当前步骤」；
来源接入、共享标准明细与清洗确认维护在 `notebooks/数据清洗/`，供多个场景引用。

## 进入

1. 先辨认任务：场景分析、来源接入/共享清洗，还是 skill/工程维护。来源任务不强行新建分析场景；
   维护任务直接核对涉及的约定，不受场景「当前步骤」限制。
2. 场景分析：查找 `notebooks/*/分析方案.md` 和已有业务方案，复用已有文档，不因文件名不同重复建档。
   新场景只在环境缺失时补第零步，再复制 `templates/分析方案.md` 从第一步开始。
3. 有场景方案 → 读头部「当前步骤」和对应 reference，推进当前步骤；依赖不成立时回前步，
   已确认且版本、字段和覆盖满足要求的来源直接复用，不重复确认。
4. 新增来源、取数接口、稳定脚本或归档时，另读 [数据与代码约定](references/数据与代码约定.md)。
   该文是工程约定的唯一入口；示例接口是目标约定，使用前核对 `src` 是否实现，不能视为现有能力。

## 三条铁律

1. **场景一份文档走全程**：各步结论写回原节，头部「当前步骤」随手更新。
   共享来源规则写来源文档，场景只记依赖、使用范围和链接，不复制另一套清洗标准。
2. **notebook 是确认回路**：清洗与指标在 notebook 里每步分开、逐条输出。
   诊断与待定项及时记文档，只有业务确认的规则才进入稳定脚本。可以一次生成诊断节，
   确认仍须逐项记录；未确认处置不执行。明细一律以**命名 dataframe** 反馈：
   - 全量明细交 dataframe，说明变量名与行数，业务用 Data Wrangler 逐笔翻；
   - 不用 head/tail/sample/Top-N 代替完整明细；手工选笔核算保留定位条件，不能代替全量核对；
   - 输出格只放全量汇总表或字段说明，不渲染整张明细；研究确认阶段不导 Excel、不整表渲染 HTML。
     最终确认的报表交付可由稳定脚本导出 Excel。
3. **后步可回退**：前步结论不成立，回对应节改并记原因，不在后步绕过。

## 三层数据

| 层 | 位置 | 谁产出 | 谁读取 |
| --- | --- | --- | --- |
| raw | `data/raw/<来源>/` | 第二步来源导入脚本，保留原始业务字段 | 第三步用 `read_raw_<来源>()` |
| processed | `data/processed/<数据集>/` | 第三步来源清洗脚本，产出共享标准明细 | 第四步用 `read_processed_<数据集>()` |
| outputs | `data/outputs/<场景>/` | 第四步场景脚本，每张结果表归档 parquet，同批生成 json | 复核用 `read_outputs()`，第五步读取该批 `data.json` |

数据流是 raw → processed → outputs。读取函数只读取指定层，不清洗、不计算、不自动换层；
processed 缺档或过期要修复上游，不能退回 raw。分区、版本、溯源和多表规则见「数据与代码约定」。

| 步 | 做什么 | 产出 | 方法 |

| 零 | 项目初始化 | 环境、依赖、目录、取数模块 | [00](references/00-项目初始化.md) |
| 一 | 业务理解与指标构建 | §一 目标 / 痛点 / 参考逻辑 / 指标 / 反推字段清单 | [01](references/01-业务理解与指标构建.md) |

| 四 | 指标验证与稳定脚本 | §四 逐步验证 / 口径调整 / 输出表清单（notebook 里按真实报表确认）+ 指标脚本 + parquet、json 归档 | [04](references/04-指标验证与稳定脚本.md) |
| 五 | 可视化看板 | §五 版式与语义约定 + 单文件静态看板（不部署） | 见下 |

**第五步·看板**：只吃第四步指定场景、业务结束日及批次的 `data.json`，不默认取最新、不算新数；
数据内嵌进 HTML，`outputs/dashboard/<场景>/<业务结束日>.html`，
双击打开即交付，不部署。页面用 visualize 技能（`.agents/skills/visualize/`）生成，不给它补算新指标；
颜色方向（降本=绿、成本上升=红）、单位、小数位、空值≠0 写进 §五，一处一个样就算没做完。

## 命令

```bash
uv run python -m unittest discover -s tests -t tests   # 测试
uv run python scripts/sync_data.py --list            # 当前仓库的采购入库归档清单
uv run python scripts/run_analysis.py --dry-run      # 当前仓库的采购增量旧入口，使用前核对层级和字段
```

新增脚本按来源/场景命名，实际命令写进方案；不要把以上两个旧入口当成多来源、多场景通用入口。
