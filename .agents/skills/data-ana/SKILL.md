# data-ana

一个完整分析场景包括方案文档、确认 notebook、稳定脚本和看板；本次只推进用户要求的范围。
场景状态记录在 `notebooks/<场景>/分析方案.md` 的「当前步骤」；共享来源的接入与清洗记录放在
`notebooks/数据清洗/`，多个场景引用同一份来源规则。

## 进入

1. 先辨认任务：场景分析、来源接入/共享清洗，还是 skill/工程维护。来源任务不强行新建分析场景；
   维护任务直接核对涉及的约定，不受场景「当前步骤」限制。
2. 场景分析：查找 `notebooks/*/分析方案.md` 和已有业务方案，复用已有文档，不因文件名不同重复建档。
   新场景只在环境缺失时补第零步，再复制 `templates/分析方案.md` 从第一步开始。
3. 有场景方案 → 读「当前步骤」和对应 reference，在用户要求的范围内推进；依赖不成立时回前步。
   已确认且版本、字段和覆盖满足要求的来源直接复用，不重复确认。用户指定的工作范围优先于状态标记。
4. 新增来源、取数接口、稳定脚本或归档时，另读 [数据与代码约定](references/数据与代码约定.md)。
   该文是工程约定的唯一入口；示例接口是目标约定，使用前核对 `src` 是否实现，不能视为现有能力。

## 工作约定

1. **场景一份文档走全程**：各步结论写回原节，头部「当前步骤」随手更新。
   每个共享数据集只维护一份清洗确认 notebook，放在 `notebooks/数据清洗/`；新增检查更新原 notebook。
   共享来源规则写来源文档，场景只记依赖、使用范围和链接，不复制另一套清洗标准。
2. **notebook 是确认回路**：诊断和待定项及时记文档，业务确认的规则才能进入稳定脚本；
   一次执行不等于业务确认，未确认的处置不执行。
   - 清洗确认 notebook 按「原始数据读取 → 已确认字段概览 → 逐字段验证 → 已确认清洗逻辑 → 清洗后完整 df」排列；
     只审查已确认字段和必要清洗输入。读取不改列名，清洗时才按确认规则命名；
   - 指标验证 notebook 按「读取 processed 原表 `df` → 按方案过滤得到 `df1` → 从 `df1` 计算指标 →
     按周期合并展示候选报表」排列；独立指标可以并行计算；
   - 一次读入 `df`。每项以简短条件筛选命名 dataframe，展示当前行数、必要汇总及明细；
     重点字段前置，其余保留在后。复用 `明细` 时注明重跑会替换，业务可用 Data Wrangler 查看完整数据；
   - 不用 head/tail/sample/Top-N 代替完整明细；手工选笔只用于复算。标题和说明从简，数字由当前数据计算。
     研究确认阶段在 notebook 展示；最终交付方式由用户确认。
3. **归档周期先确认**：新增场景或调整归档时，若用户尚未明确周期，先问按日、周、月还是其他周期归档，并确认业务周期边界和归档日期；已确认的不重复询问。记录到方案，再实现归档。
4. **后步可回退**：前步结论不成立，回对应节改并记原因，不在后步绕过。

## 三层数据

| 层 | 位置 | 谁产出 | 谁读取 |
| --- | --- | --- | --- |
| raw | DuckDB `raw.<来源>` | 第二步来源导入脚本，保留原始业务字段 | 第三步用 `read_raw_<来源>()` |
| processed | DuckDB `processed.<数据集>` | 第三步来源清洗脚本，产出共享标准明细 | 第四步用 `read_processed_<数据集>()` |
| outputs | DuckDB `outputs.<场景>__<表>` | 第四步场景脚本，按业务周期保存各结果表 | 复核用 `read_outputs()`，看板按需查询 |

数据流是 raw → processed → outputs。读取函数只读取指定层，不清洗、不计算、不自动换层；
正式运行时 processed 缺档、过期或覆盖无法确认，先修复或核实上游，不能退回 raw。
分区、版本、溯源和多表规则见「数据与代码约定」。
