# data-ana：场景化数据分析

把一个业务问题做成**可复跑的分析产品**：一份方案文档、一组确认 notebook、一套稳定脚本、一个看板。
最小工作单位是**场景**——一个场景 = 一个这样的产品。
每个场景的全部状态都在一份文档里：`notebooks/<场景>/分析方案.md`，头部记着「当前步骤」。

## 进入：先做这三件事

1. `ls notebooks/*/分析方案.md` 发现场景。
2. 读目标场景的方案文档，看头部「当前步骤」，**只做当前步**；
   进哪步就读哪篇 references（见「五步」表），不要一次全读。
3. 没有方案文档就是新场景：复制 `templates/分析方案.md` 到 `notebooks/<场景>/` 建档，
   从第一步开始。

## 三条铁律

1. **一份文档走全程**：五个步骤依次**追加**在同一份分析方案上，不另开文档、不拆多份
   ——方案只有一份，才不会越写越散。
2. **notebook 是确认回路**：清洗与指标计算在 notebook 里**每步分开、逐条输出**，
   业务方看完反馈、确认后才落笔到方案、才沉淀脚本
   ——一次性跑完再给人看，等于没有确认。
3. **五步可回退**：后步发现前步结论不成立（清洗后指标算不了、验证与业务认知矛盾），
   回到对应节修改并记变更原因，不在后步悄悄绕过；文档头部「当前步骤」随之更新。

## 五步

| 步 | 内容 | 产出（追加到分析方案.md） | 方法 |
| --- | --- | --- | --- |
| 一 | 业务理解与指标构建 | §一 目标 / 痛点 / 已有参考逻辑 / 指标 / 反推字段清单 | [01-业务理解与指标构建.md](references/01-业务理解与指标构建.md) |
| 二 | 数据源与归档 | §二 业务供数 / 字段对照（对照 §一 清单）/ 归档方案（优先按日期 parquet） | [02-数据源与归档.md](references/02-数据源与归档.md) |
| 三 | 数据清洗与聚合 | §三 异常逐项确认 / 清洗逻辑 / 聚合逻辑 + 确认 notebook（模板见 templates/数据清洗模版.ipynb） | [03-数据清洗与聚合.md](references/03-数据清洗与聚合.md) |
| 四 | 指标验证与稳定脚本 | §四 逐步验证 / 口径调整记录 / 稳定脚本 + 研究 notebook（模板见 templates/指标验证模版.ipynb） | [04-指标验证与稳定脚本.md](references/04-指标验证与稳定脚本.md) |
| 五 | 可视化看板 | §五 版式与语义约定 + HTML 看板 | 待补 |

各步要点：

- 第一步**不看任何原始表**，字段从指标反推，不从表反推。
- 第二步字段对照有缺口 → 和业务谈数据或替代方案，不硬凑。
- 第三步多表聚合要确认理解一致性。
- 第四步确认后才形成稳定脚本，同步调整前面的文档。
- 第五步数据只从第四步产出取，看板不算新数。
