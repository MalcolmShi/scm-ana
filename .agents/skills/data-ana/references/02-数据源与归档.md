# 第二步：数据源与归档

确定指标所需字段来自哪里，并将原始数据写入 DuckDB raw。已有来源满足字段、口径和覆盖时直接复用。

1. **确认来源**：记录提供方、更新频率、覆盖范围和业务已知问题；将缺失数据及影响记为待确认。
2. **确认字段**：对照第一步的字段清单，记录源字段 → processed 标准字段 → 场景用途，以及单位、税口径和必要的清洗输入。缺字段或替代口径由业务确认。展示其他可用字段供业务选择，但不把本场景的投影当成共享底表的裁列清单。
3. **确认入库方式**：区分按业务日的增量明细与全量快照。记录业务日期、覆盖、更新频率、重复导入和更正规则；全量快照需明确选取哪一版，不能拼接多版重复计数。未经确认的缺日不当作零。
4. **接入并核对**：来源模块读取实际来源，调用 raw 写入接口；raw 保留源字段和取值。用 `read_raw_<来源>()` 读回，核对行数、金额和日期覆盖；无效日期或不明丢行应报告并停止。

在方案 2.1–2.3 记录来源、字段对照、数据表、接入命令和核对结果。来源缺失或口径未确认时说明阻塞，不声称接入完成。
