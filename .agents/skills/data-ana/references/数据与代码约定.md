# 数据与代码约定

新增来源、读取入口、分析或归档时读本篇。DuckDB 是项目主要存储；旧 Parquet 作为迁移输入和备份保留，不作为默认读取路径。

## 数据与周期

- `data/scm.duckdb` 中按 `raw`、`processed`、`outputs` schema 分层。raw 保留源字段和取值；processed 是共享清洗明细；outputs 保存已确认的场景结果。
- 新增或调整归档时，若周期尚未明确，先询问用户按日、周、月还是其他周期，并确认业务结束日、实际归档日期及重跑方式。已确认的周期不重复问。
- 业务日期与归档日期分别记录。同一期重跑事务替换该期结果；如需保留历史版本，先明确要求。
- 没有归档可能是无业务、未提供或失败，不能默认当零。读取 processed 时对照已知 raw 分区，缺档或确定已过期即报错；缺少原始版本证据标为未核实。
- 明细和汇总分开：逐笔下钻读取相同窗口和过滤条件下的 processed；不能把汇总列中的多值列表当作逐笔对应关系。

## 代码职责

| 位置 | 职责 |
| --- | --- |
| `src/storage.py` | 通用数据库连接、按数据集和业务日读写、按场景和周期事务写入结果；不知道具体业务名称或规则 |
| `src/read_data.py` | 按层命名的读取入口：`read_raw_<来源>()`、`read_processed_<数据集>()`、`read_outputs()`；不自动换层 |
| `src/write_data.py` | 按层命名的写入入口；数据源专属的日期和字段校验放在对应入口 |
| `src/sources/<来源>.py` | 该来源的文件、接口及导入规则 |
| `src/clean/<数据集>.py` | `clean_<数据集>(frame)`：只处理明细并返回处置台账 |
| `src/analysis/<场景>.py` | `analyze(frame, config)`：只计算，返回命名结果表；不隐式读取或写入 |
| `src/services/<场景>.py` | 该场景的本地查询、过滤和下钻；复用确认的结果和 processed 明细 |
| `scripts/` | 按来源或场景串联读、处理、校验、写入 |

新增来源：补来源模块、清洗规则及明确命名的读写入口，复用 `storage`；不能在通用存储中写死来源名。新增分析：补分析模块和场景入口，输入 processed，结果写 outputs；不能在通用存储中写死场景名。

## 接口与校验

```python
from read_data import read_raw_procurement_inbound, read_processed_procurement_inbound, read_outputs
raw = read_raw_procurement_inbound('2026-09')
processed = read_processed_procurement_inbound('2025-10', '2026-09')
report = read_outputs('procurement_increment', '2026-09-30')
```

一个日期参数表示完整年、月或日；两个参数表示闭区间。普通入口返回 DataFrame，需要元数据时使用 `_meta()`。读取只访问指定层，不清洗、计算或自动换层。

记录输入分区指纹、规则/代码版本、参数、业务结束日和归档日期。结果多表必须同一事务写入，失败回滚；正式字段类型和粒度明确，不静默兼容字段增删或类型变化。验证不同来源隔离、缺档和过期失败、清洗与分析衔接、指标边界、下钻明细与汇总对账。
