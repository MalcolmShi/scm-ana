# 数据与代码约定

新增来源、取数接口、清洗/分析脚本或归档时读本篇。步骤 reference 负责业务确认，
本篇统一工程约定。**以下是目标约定，不表示当前 `src` 已全部实现。**
使用前检查实现；缺能力就明确补齐并验证，不用旧的隐式换层行为兼容过去。
只修改 skill 的任务不自动扩展为代码重构或数据迁移。

## 1. 来源、数据集与场景

- **来源**回答数据从哪来：导出文件、系统表或接口；接入、原始字段和清洗规则维护在
  `notebooks/数据清洗/` 的对应来源文档及 notebook，复用已有文件名。
- **processed 数据集**是一份可复用的标准明细，有固定粒度、键、字段、类型、单位、空值与日期含义。
  单来源时默认沿用来源 id；确需多来源共享明细时另取数据集 id，声明各来源与关联规则。
- **场景**依赖一份或多份 processed 数据集，负责业务范围、聚合、衍生指标与结果。
  场景字段清单是读取投影，不能据此裁掉其他场景需要的共享底表字段。
- 共享标准新增、改名、删字段或改单位时，先检查已声明的消费场景；破坏性改动明确版本与迁移，
  不能覆盖原定义后让分析自行猜测。只为单场景计算的衍生字段放分析模块。

## 2. 读取接口按层命名

```python
# 接口示意；按真实来源/数据集替换名称，先检查实现
from read_data import (
    read_raw_procurement_inbound,
    read_processed_procurement_inbound,
    read_outputs,
)

raw = read_raw_procurement_inbound("2026-09")
inbound = read_processed_procurement_inbound("2025-10", "2026-09")
report = read_outputs("采购增量分析", "2026-09-30", table="detail", batch_id="本次运行的批次标识")
```

- notebook 常用接口返回 `DataFrame`；生产脚本需要留痕时使用同语义的 `*_meta()`，
  返回 `(DataFrame, meta)`，共用读取实现，不另造一套取数逻辑。
- 读取只做指定层的文件选择、选列、必要的日期裁剪和拼接；不改业务列名、不清洗、不补算，
  不按文件是否存在自动换层，也不混合不同 schema 版本。
- 业务日明细：一个参数表示完整年/月/日周期，两个参数表示闭区间；无参数表示该层全部分区。
  日期解析、分区发现、选列与拼接由公共存储模块实现，不在每个来源里复制线程和扫描逻辑。
- 全量快照：按快照版本读一份，不能套用日明细拼接语义。第二步先确认属于哪一种。
- outputs 按场景、业务结束日和结果表读取一批结果，不跨期拼接滚动窗口报表。
  复核与看板固定批次；若提供「最新」便利入口，需显式选择并返回实际版本，不能默认使用。
- `meta` 记录请求窗口、实际分区与输入文件版本/指纹、层、schema/规则版本、行数、覆盖与缺失情况。
  覆盖说明放在 `coverage`，包含实际覆盖与缺口，不限于月份。
  不用首个文件代表整个窗口，也不把混层结果标成 raw。

## 3. 覆盖完整性与时效

- 没有文件可能是无业务、未提供、导入失败或未清洗，不能统一当成零。
  来源文档声明覆盖期间、更新频率及无业务日期的识别依据；来源导入记录实际接收的覆盖。
- processed 读取对照该窗口应处理的 raw 分区/输入版本：缺日、过期或版本不兼容时列明原因并报错，
  不能过滤掉缺档后返回一个看似完整的窗口。raw 本身覆盖不足也要明确暴露。
- 部分窗口的探索必须显式说明实际覆盖和缺口，不能据此宣布正式分析窗口完整。
- raw 重导入后，依赖旧输入的 processed 和 outputs 视为待重算；文件存在不等于结果仍有效。

## 4. 路径、更新与溯源

业务日明细默认沿用本项目布局：

```text
data/raw/<来源>/<YYYY>/<YYYY-MM>/<业务日>/data.parquet
data/processed/<数据集>/<YYYY>/<YYYY-MM>/<业务日>/data.parquet
data/outputs/<场景>/<YYYY>/<YYYY-MM>/<业务结束日>/
    data.parquet                 # 主结果表，对应 JSON tables.detail
    tables/<结果表名>.parquet     # 其他已确认的结果表
    data.json                    # 同批所有结果表，供看板消费
    manifest.json                # 批次、输入、参数、版本和表文件清单
```

- raw 保留原始业务列名、取值和单位；已存在的 `_source`、`_fetched_at` 不在读取时偷偷改名。
  元数据字段、取数时间、清洗时间分别在来源文档声明，不能让 `updated_at` 同时表示多种时间。
- raw 相同输入重复导入应幂等；同分区输入发生变化不能静默覆盖。更正时保留旧输入版本及原因，
  版本位置与引用方式写进第二步归档方案。保留原始导出文件及导入记录，以便追溯转换前的数据。
- processed 可按受影响分区重建；记录输入文件版本/指纹、清洗规则版本和处理时间。
  版本/指纹必须能识别同路径内容变化，不能只记录路径或最大业务日。
- outputs 的业务结束日、实际输入版本、计算时间分别记录。每批 `manifest.json` 至少包含
  批次标识、业务窗口、输入文件及版本/指纹、schema/规则/代码版本、参数、结果表路径与行数。
- 每张确认结果表都落 parquet；JSON 从这些同批结果表生成，表名、列名、行数、空值和指标值一致。
  JSON 保持 `meta` + `tables`，每表为 `columns` + `rows`，NaN 转 `null`，保留空值与零的区别。
- 先在临时批次生成并校验全部文件，成功后才发布为可读批次；失败保留上一完整批次。
  多文件逐个原子替换不等于整批一致；同业务结束日重跑需保留可追溯的运行记录。
  上述日期目录展示已发布结果；历史批次的留存位置、批次查找和发布方式在实现时明确，
  固定 `batch_id` 必须可读回原批次，不能只保留最后一次覆盖的文件。
  存量单表归档继续可识别，多表/批次能力缺失时先补实现，不能声称已满足本约定。

## 5. 稳定模块各自负责什么

| 位置 | 职责 |
| --- | --- |
| `src/archive.py` | 公共路径、分区/版本发现、日期窗口、parquet 读写与覆盖校验；提供 `write_outputs(tables, scene, snapshot_date, meta)` 的批次归档入口，内部可拆分实现；不绑定具体来源 |
| `src/read_data.py` | 显式 `read_raw_*`、`read_processed_*`、`read_outputs` 入口；不转出来源画像常量充当通用能力 |
| `src/sources/<来源>.py` | 来源结构、接入、原样归档；不复制公共存储读取逻辑 |
| `src/clean/<数据集>.py` | `clean_*(frame, config)`：标准化明细并返回处置台账；读写由调用入口串联 |
| `src/analysis/<场景>.py` | `analyze(frame, config)`，多输入时显式接收各表；校验输入后做业务过滤、聚合和指标，返回命名结果表与元数据 |
| `src/reporting/` | 消费已计算结果，生成报表；场景专用字段、说明和样式按场景命名 |
| `scripts/` | 按来源/场景命名，串联读、处理、校验、写；不在通用 `analyze()` 中写死一个场景 |

新增来源只补来源接入、标准化规则与显式读取入口；新增场景声明 processed 依赖、计算和输出。
沿用当前模块组织即可，不为扩展预建注册框架。可变窗口、阈值放参数；稳定 schema 与已确认的业务常量
可以命名常量表达，不要求所有字段和映射强行塞进 Config。

## 6. 验证跨层约定

合成数据验证有意义的行为：指定层读取不换层；缺档/过期失败；清洗输出能被真实分析入口接收；
规则变更能暴露受影响场景；多来源 join 的基数和金额勾稽；同批所有 parquet 与 JSON 对拍，
失败发布不暴露半批结果。指标另测边界与总账，不用分别 mock 掉上下游后宣称整条链路可用。
