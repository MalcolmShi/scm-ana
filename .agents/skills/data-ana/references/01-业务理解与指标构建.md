# 第一步：业务理解与指标构建

> 产出：分析方案.md 的「一、业务理解与指标构建」。先明确业务目标与指标，再核对数据可得性。

## 怎么做

1. **把业务目标问清楚**（1.1）：这份分析支撑什么决定、做完之后业务拿它做什么。要可判断的表述，不要口号。
2. **把痛点问实**（1.2）：现在卡在哪、靠什么人工方式顶着、出过错吗。业务方原话照抄，转述会失真。
3. **盘点已有参考与确认逻辑**（1.3）：业务现在看哪些数和报表、目前怎么人工确认这件事（找谁问、对什么表）。
   这是后面口径对账和验证的基线——新指标要么和它对得上，要么能解释差在哪。
4. **构建指标**（1.4）：从目标出发定指标，每个指标写 名称 / 定义 / 计算公式 / 常用维度 / 统计周期。
   同时明确一行代表什么、金额税口径与单位、空值/零/无业务的区别。
   想不全没关系，先写下来让业务确认，逐步补齐。
5. **反推字段清单**（1.5）：逐个指标拆公式，列出需要的数据列——事实列、维度列、日期列。
   先列业务概念，不因现有表的字段限制目标；第二步再绑定到具体来源和标准数据集。

## 规则

- **不从表反推目标**：可查已有方案、字段目录与参考报表来澄清概念，但不能用「表里有什么」替代业务需求。
  数据能否提供、字段如何映射在第二步核对。
- 业务答不上来的，标「待确认」并写明卡在哪，不猜、不编。
- 指标之间有依赖的（A 用 B 的结果），写明依赖。
- 1.5 是第二步的验收标准：下一步拿业务给的数据源跟这份清单对照，缺什么在这一步就该暴露。

## 完成标志

1.1~1.5 五小节都有内容，业务方对 1.4 的指标、1.5 的字段清单点头。之后才进第二步（数据源与归档）。
