# 第零步：项目初始化

> 产出：能跑的 uv Python 环境、齐的依赖、对的目录骨架、通的数据通道。
> 一次到位，后续所有步骤直接开工；没有这一步，第三步取数、第四步测试都是空谈。

## 怎么做

1. **uv 环境与依赖**：

   ```bash
   uv init            # 已有 pyproject.toml 则跳过
   uv add pandas numpy pyarrow jupyter openpyxl
   ```

   | 包 | 干什么 |
   | --- | --- |
   | pandas / numpy | 清洗、聚合、指标计算 |
   | pyarrow | parquet 读写（raw 日档与 processed 归档都靠它） |
   | jupyter | 确认 notebook 的运行环境 |
   | openpyxl | 业务 Excel 导入导出（sync_data 通道用） |

   后续步骤用到再补（如绘图库），不一次堆满。

2. **目录骨架**（已存在的跳过，不覆盖）：

   ```
   src/        # 稳定代码：sources 取数 / clean 清洗 / analysis 指标 / reporting 导出（含 metrics 归档）
   scripts/    # sync_data.py（Excel → raw 日档）等命令入口
   notebooks/  # <场景>/ 分析方案.md + 确认 notebook
   data/       # raw/（原始日档，只追加） processed/（清洗归档） outputs/（指标结果：parquet + json）
   outputs/    # dashboard/<场景>/<业务结束日>.html（看板） reports/（报表等交付物）
   tests/      # 离线测试（合成数据，不依赖真实归档）
   ```

   三层各归各的脚本产出（raw ← sync_data、processed ← 第三步清洗脚本、
   outputs ← 第四步指标脚本），取数只从下游层读，不跨层、不回头改上游。
   `data/` 存数据、`outputs/` 存交付物：看板 html 与报表都进 `outputs/`，不回写 `data/`。

3. **取数模块**：`src/read_data.py` 提供**按日期读 raw** 的函数
   （如 `read_inbound(起始日, 结束日)`，支持单周期与时间范围），
   底层按 `data/raw/<源>/<年>/<月>/<日>/data.parquet` 分区拼接。
   第三步清洗 notebook、第四步验证 notebook 都从这里取数。

4. **冒烟验证**（三样都过才算初始化完成）：

   ```bash
   uv run python -c "import pandas, numpy, pyarrow; print('deps ok')"
   uv run python -c "from read_data import read_inbound; df = read_inbound('2026-09-01','2026-09-30'); print(len(df), 'rows')"
   uv run python -m unittest discover -s tests -t tests
   ```

## 规则

- 环境一律走 uv（`uv run` / `uv add`），不用裸 pip；锁文件（uv.lock）进版本库。
- 三层各归各的产出脚本：raw 由 sync_data 只追加、processed 由第三步清洗脚本产出、
  outputs 由第四步指标脚本产出；任何层都不手改。
- 依赖进 pyproject，不装全局；notebook 里 import 的包必须已在 pyproject 里。
