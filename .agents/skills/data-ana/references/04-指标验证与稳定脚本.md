# 第四步：指标验证与稳定脚本

读取 DuckDB processed，按方案验证指标，确认报表后实现分析脚本并保存 outputs。来源或清洗口径有问题时回对应步骤处理。

## 指标确认

使用 `templates/指标验证模版.ipynb`，按实际数据集替换示例：

1. 读取 processed 完整 `df`；读取单元只保留导入、窗口和取数，不堆叠工程校验。
2. 按确认的时间、范围和金额条件过滤得到 `df1`，展示完整字段，重点字段前置。
3. 从 `df1` 逐项计算并展示指标及对应明细；独立指标可并行，依赖相同月度基础数据的指标复用它。说明粒度、周期、公式和实际行数；周期补零属于汇总结果，不伪造逐笔明细。
4. 按业务确认的键和周期合并指标，展示汇总报表；明细的日期、数量和金额不拼成多值列表，逐笔信息通过 processed 明细查看。
5. 对照业务参考数、可定位的明细和汇总总账；差异查清原因并记录。只在展示时舍入，不把空值当零。

## 脚本与结果

- 确认每张结果表的业务用途、粒度、键、字段、单位和更新周期；归档周期及业务边界尚未明确时先问用户。
- 分析函数接收 processed 数据和参数，返回命名结果表；入口脚本负责读取、计算、校验和写入。清洗逻辑留在共享清洗模块。
- 同一业务周期的结果表在一个事务中写入 DuckDB outputs，重跑替换该周期；记录业务结束日、归档日期、输入版本、规则版本和参数。
- 按指定周期读回每张表，对拍字段、行数、空值和指标；覆盖缺失、输入过期或版本未核实应明确报告，不能静默退回 raw。
- 方案记录实际命令、结果表及对账结论；合成数据验证指标边界和来源 → 清洗 → 分析的衔接。
