# 第四步：指标验证与稳定脚本

> 产出：分析方案.md 的「四、指标验证与稳定脚本」+ 指标验证 notebook
> （模板：`templates/指标验证模版.ipynb`）；确认后把计算沉淀成稳定脚本。

## 怎么做

1. **一个指标一节、逐步展示**：验证 notebook 每节算一个指标，中间结果、分组明细
   都摆出来，每格以表格收尾——用户能自己核，不是只看结论。
2. **每个指标先声明粒度**：一行代表什么（一个物料×一个月？一张单？），加总是什么。
   粒度没说清，后面所有对账都是糊涂账。
3. **对账三件套**（对得上才算数）：
   - **对业务已知数**：1.3 盘出来的现有报表、口头数——对不上必须解释差异来源；
   - **对明细**：抽几笔手工按公式算，和结果对；
   - **对总账**：分层对——明细行数金额 → 分组小计 → 总计，逐层加总一致；
     有期初期末的（库存、余额类）首尾也要勾稽。
4. **对不上不许「解释过去」**：差异要么口径错、要么数据错、要么参照数本身错，
   查到根因才能继续；靠说法圆过去的不算对账。
5. **口径调整走回路**：算不出、或结果不符合业务认知 → 回 1.4 改原节，
   在 4.2 记「改了什么 / 为什么 / 谁同意」；不在 notebook 里悄悄绕。
6. **确认后沉淀稳定脚本**：
   - 验证过的计算逐段搬进 src（分层去向：取数 sources / 清洗 clean / 指标 analysis / 导出 reporting）；
   - 窗口、阈值全收进 Config 参数，不写死；
   - 离线测试：合成小数据跑关键断言（清洗勾稽、指标边界、分层加总）；
   - 一条命令复跑，输出物路径写进 4.3。
7. **沉淀后对拍**：同窗口下稳定脚本结果与验证 notebook 逐数一致，一致才算落地。

## 规则

- 业务没确认的口径不进 src，留在 notebook。
- 测试用合成数据，不依赖真实归档。
- 输出物自带数据口径信息（窗口、数据时点、来源文件）——报告要能自证来路。
- 稳定脚本的产出是第五步可视化的直接输入，第五步不重算。

## 完成标志

4.1~4.3 齐备：每个指标在 notebook 可复算、三件套对账通过；口径变更全记录在 4.2；
稳定脚本一条命令复跑、与 notebook 对拍一致、测试全绿。之后进第五步（可视化方案）。
