# 第三步：数据清洗与聚合

输入是 DuckDB raw。每个共享数据集维护一份清洗确认 notebook 和来源文档；符合本场景字段、规则和覆盖要求的 processed 可以直接复用。

## 清洗确认

notebook 按以下顺序排列，文字和代码保持简洁：

1. 用 `read_raw_<来源>()` 一次读取完整窗口的 `df`，保留原始列名。
2. 概览已确认字段及必要清洗输入的类型、空值和取值情况，确定需要核查的内容。
3. 按确认字段逐项验证：说明条件，从 `df` 过滤 `明细`，展示行数、必要汇总和完整字段；重点字段前置。根据字段特点检查缺失、格式、重复、数值和勾稽，不把统计异常自动当作业务错误。复用 `明细` 时说明运行下一项会覆盖它。
4. 在相应检查旁记录已确认的处理和待定问题；字段相同只代表重复候选，未确认不删除。
5. 汇总已确认的清洗规则，在内存生成并展示完整 `cleaned`。业务确认前不执行未确认的填补、覆盖或剔除。

清洗确认模板见 `templates/数据清洗模版.ipynb`；按实际来源替换示例并删除无关内容。

## 落地与衔接

- 业务确认后实现或复用 `clean_<数据集>(frame)`，由入口脚本读取 raw、清洗并写入 DuckDB processed；保留明细粒度，重复记录按确认结果处理。
- 记录清洗规则、输入版本、命令和覆盖；对比 notebook 与脚本的字段、行数、关键明细及金额，确认结果可读回。覆盖或输入版本无法核实的注明待核实。
- 场景过滤、聚合和衍生指标在第四步处理；涉及多表关联时确认关联键、基数、未匹配记录及关联前后的行数和金额。
- 共享来源文档记录清洗结论，场景方案引用它。未确认且影响结果的问题留在本步骤解决。
