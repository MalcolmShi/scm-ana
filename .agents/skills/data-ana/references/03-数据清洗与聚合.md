# 第三步：数据清洗与聚合

> 产出：分析方案.md 的「三、数据清洗与聚合」+ 一个逐项确认的清洗 notebook
> + 清洗稳定脚本 + processed 归档。
> 输入是第二步已归档的数据，**清洗只围绕第二步表 A 勾选的字段展开**——
> 全列画像仍看全表（用于发现意外问题），处置和 processed 底表只含选中字段；
> 一切清洗在内存里预演，raw 永不动。业务确认清洗后完整 df 之后，
> 才沉淀脚本、落 processed 归档；第四步起一律从 processed 归档取数。

## 怎么做

1. **先画像，后逐类**：清洗 notebook 第一节给全列画像——类型、空值率、唯一值数、
   Top 值、数值列分位。用它定位可疑列（空值率畸高、唯一值数=1 的零方差列、类型混杂），
   定排查优先级。画像只是地图，异常结论要逐类核实。

2. **按质量维度系统枚举异常，不想到哪查到哪**：

   | 维度 | 查什么 | 例子 |
   | --- | --- | --- |
   | 唯一性 | 完全重复行；业务键重复 | 同一单号+物料多行：真重复还是合法多次？问业务 |
   | 完整性 | 关键字段空值、整行空 | 维度键空→行无法归属；金额数量空→无法聚合 |
   | 有效性 | 类型格式、枚举域、编码、脏字符 | 日期不像日期、千分位/全角数字、域外枚举、\r\n 与 _x000d_ |
   | 一致性 | 行内勾稽、跨表矛盾 | 单价×数量≈金额？单位全表唯一？两边同一事实对不上 |
   | 准确性 | 业务规则违背、离群值 | 负数、成本倒挂、未来日期、金额极端值 |
   | 及时性 | 覆盖断档、更新滞后 | 缺月缺日、快照落后业务期 |

3. **排查有顺序**：结构格式 → 重复 → 空值 → 勾稽 → 离群。
   前面不干净会污染后面：没去重时离群被重复行放大，格式没统一时空值统计都不对。

4. **notebook 一次生成，逐项确认**：全部排查节**一口气生成并执行完**（省去每节
   等一轮的来回），但**确认仍然一项一项过**——按节逐项给业务看、有异议改了重跑
   对应节；确认一类过一类，绝不因为一次生成就把确认也囫囵吞掉。
   notebook 骨架见 `templates/数据清洗模版.ipynb`，复制改名即用，措辞面向业务方。
   **每节汇报统一三段式**，业务只看这三块就够：
   - **总结**：一两句话——影响多少行/多少钱、要不要紧、结论倾向；
   - **明细**：三视图样本（影响排序 Top + 分层随机 + 可自查定位），
     多行问题按组展示，一组一行摘要；
   - **建议**：修格式 / 剔除（记行数金额）/ 保留并标注，一句话理由 + 待拍板项。

5. **处置只有三种，逐一留痕**：格式修复 / 剔除（记行数与金额）/ 保留并标注。
   离群值特殊：统计方法（分位、IQR）只负责**产生候选**，处置必须由业务规则裁决；
   拿不准的标「待确认」，不自行删改。

6. **落笔 3.1 / 3.2**：每类异常记「维度 / 现象 / 行数 / 处置 / 业务结论」；
   清洗逻辑成文（动哪个字段、怎么动、为什么）。

7. **清洗后完整 df 确认 → 落 processed 归档**（第三步的收口，缺一不可）：
   - notebook 末尾把确认过的处理全部套上，输出**清洗后完整 df**：全量展示或导出文件
     （禁止 head/截断），并**主动提醒业务逐列过目确认**——这是进 processed 前的
     最后一道关，确认了才往下走；
   - 确认后**立即沉淀清洗稳定脚本**：验证过的清洗链逐段搬进 src 清洗层，
     窗口、阈值、映射表全收进 Config，不写死；
   - 跑脚本产出 processed 数据并**归档**，分区规则与 raw 归档一致（优先按日期 parquet）；
   - 脚本结果与 notebook 预演**对拍一致**（行数、金额逐项相同）才算落地；
   - 业务未拍板的待定项（如挂起的重复行处置）不进稳定脚本，留在 notebook 并在 3.1 标注；
   - 落笔 3.4：脚本入口命令、归档路径、对拍结论。

8. **聚合逻辑对齐**（3.3）：多表 / 多来源聚合时，聚合口径逐项和业务对——
   按什么键 join、一对多怎么摊、单位怎么统一（元 / 万元）、两边对同一指标的理解是否一致。
   对过的写进 3.3，没对过的标「待确认」。

## 规则

- 检查过的维度即使零异常也记一笔（「查过、干净」也是结论，防漏查防重查）。
- 每类异常先给行数和占比，按量排优先级——量化优先于感觉。
- 只做格式转换，不改业务原值；确要改值的（列合并、覆盖），单独列出并做勾稽验证。
- 剔除必须留痕：剔了多少行、多少钱，写进 3.1。
- 业务没确认的处置不落笔、不进下一步。
- 清洗后完整 df 业务没确认 → 不沉淀脚本、不写 processed；processed 归档是第四步起
  取数的**唯一来源**，后续步骤不再从 raw 内存预演、不重放清洗逻辑。
- 数据源级的清洗 notebook 放 `notebooks/数据清洗/`，场景内的聚合与衍生计算放场景目录。

## 完成标志

3.1~3.4 齐备：六个维度都有排查记录与业务结论、清洗预演在 notebook 可复现、
聚合口径逐项对过；清洗后完整 df 业务确认、清洗稳定脚本与 notebook 对拍一致、
processed 归档完成。之后进第四步（指标验证与稳定脚本）。
