# 02 · 口径定义（规范）

> **本文档是第 2 步的验收规范。** 基于 01 签署的意图，把每个指标的口径写死。
> 按 `templates/口径确认表.md` 填写，业务方签署后进第 3 步（取数）。

口径是整条链路里**唯一会因为一句话说得含糊而返工**的东西。
「最近」是三个月还是半年、「金额」含不含税，这两个问题没定清楚，代码写完也得重写。

## 一、指标口径

### 1.1 指标清单

**填写要求**：先列全，再逐个定口径。

| # | 指标名 | 支撑 01 意图的哪部分 | 是原子指标还是计算指标 |
| --- | --- | --- | --- |
| 1 | | | 原子（直接取数）/ 计算（有公式） |

**合格判据**：

- [ ] 每个指标都能对应到 01 签署的意图，没有「顺手也算了」的指标
- [ ] 标的了原子还是计算——原子指标写「直接取数」，计算指标必须有公式

**能算不等于该算。** 源表几十列，能派生的指标很多，但只有支撑意图的才进清单。

### 1.2 四件套

**填写要求**：每个指标四件套必须齐全。

| 指标 | 分子 | 分母 | 统计周期 | 数据来源字段 | 负责人 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

| 项 | 填写要求 | 不合格的写法 |
| --- | --- | --- | --- |
| 分子 | 算的是什么，取哪个字段 | 「金额」——不说含税还是不含税、含不含退款冲减 |
| 分母 | 除以什么；无分母写「—」 | 空着，或者写「除以数量」但不说数量含不含退货 |
| 统计周期 | 具体时间窗，含起止规则 | 「最近」——不说 3 个月还是 6 个月 |
| 数据来源字段 | 具体字段名 + 哪一层（raw / processed） | 「从 ERP 取」——不说哪个字段 |
| 负责人 | 具体的人或岗位 | 「业务方」 |

**合格判据**：

- [ ] 五列都有值，无分母的写「—」不是空
- [ ] 统计周期含起止规则（如「自然月，月初到月末」而不是「按月」）
- [ ] 数据来源精确到字段名和层级
- [ ] 负责人是具体的人或岗位
- [ ] 全文没有「最近」「大概」「原则上」「一般情况下」这类词

### 1.3 常见缺口

这四类最常见，写的时候逐条对照：

| 缺口 | 表现 | 后果 |
| --- | --- | --- |
| 时间含糊 | 「最近」「近期」「这段时间」 | 换个时间窗结果完全不同 |
| 口径混用 | 含税价和不含税价在同一列里比 | 算出来的金额是假的 |
| 冲减未计 | 只算正向，不算退货/红冲 | 金额系统性偏高 |
| 归属不清 | 一笔业务算给谁不明确 | 分主体汇总时重复或遗漏 |

## 二、阈值

### 2.1 取值与业务理由

**填写要求**：每个阈值必须有业务理由，不能写「经验值」。

| 常量名 | 取值 | 业务理由 | 改动的后果 |
| --- | --- | --- | --- |
| | | | |

**合格判据**：

- [ ] 每个阈值都有业务理由，且理由是**业务事实**不是同义反复
- [ ] 没有「经验值」「拍脑袋」「一直是这样」这类理由
- [ ] 「改动的后果」两向都写了（调高怎样、调低怎样）

**合格的写法**：写明它对应什么成本、收益或业务事实。例如——
「低于 5 万的记录，全年可争取的收益上限不足以覆盖一次处理流程的人力成本」。

**不合格的写法**：
- 「经验值」——半年后没人知道为什么是这个数，也没人敢改
- 「行业惯例」——哪个行业、哪份惯例，说不出就是没有
- 「领导定的」——等于没有理由，换领导就得重定

### 2.2 改动的后果

「改动的后果」这一列决定了阈值能不能被安全调整。没有这一列，阈值就是不可碰的黑箱。

| 阈值 | 调低会怎样 | 调高会怎样 |
| --- | --- | --- |
| | | |

**合格判据**：每个阈值两向都写了，且写的是**业务后果**不是技术描述。

## 三、边界行为

阈值取等号算不算通过？分母为 0 怎么办？这些不能留到写代码时临时决定。

### 3.1 三类必定的边界

| 情况 | 必须写明 | 常见做法 |
| --- | --- | --- |
| 阈值恰好相等 | 算通过还是不通过 | 准入门槛用「严格大于」，等于门槛不通过 |
| 分母为 0 | 留空、置 0、还是单列一档 | 留 `NaN`，单列一档「无基线」，不参与排名 |
| 基期 ≤ 0 | 同上 | 前期净负值也归入「无基线」档 |
| 无数据周期 | 补零、剔除、还是报错 | 窗口缺周期直接报错，不补零 |

**合格判据**：

- [ ] 四类边界都写了处理方式，没有「视情况而定」
- [ ] 处理方式能直接翻译成代码分支

### 3.2 留空优先

**无意义的计算留 `NaN`，不要给 `inf` 或 `0`。**

原因见 `05-分析与提取.md` 的「留空原则」：`inf` 会同时满足阈值和排序条件，
把噪声顶到榜首；而 `0` 会被当成「实际发生但金额为零」，污染平均值。

**合格判据**：全文没有「除数为 0 时置 0」这种处理。
