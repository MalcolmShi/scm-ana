## 一、四条原则

### 1. 留空原则：无意义的计算要留空，不能给 `inf` 或 `0`

**例（真实，已修）**：某个增长率指标

```
趋势指数 = 最近3期均值 / 前3期均值 - 1
```

基期为 0 时除法得 `inf`。而 **`inf` 同时满足「>= 20%」和「降序排第一」**，
会把刚开始有数据的新记录直接顶到排名榜首。

这不是计算错误，是**把噪声当成了最强信号**——而且它排在第一位，看报告的人第一眼就看到它。

**做法**：`baseline.where(baseline > 0)`，无基期留 `NaN`，单列一档「无基线」，不参与排名。
同理，`0` 不能随便用来表示「不适用」，见 `03-取数与清洗.md` 的符号原则。

### 2. 门禁原则：数据不完整就报错，不要补零糊过去

**例（真实，已防）**：周期汇总会为每个实体补齐完整时间轴，缺期补 `0`。
补零让「最近 3 期均值」偏小，增长指标虚高，最后生成一份看起来很漂亮但错的报告。

**做法**：进分析前先校验窗口内周期齐全，缺期直接 `ValueError` 并列出缺哪几期。

> **宁可跑不出报告，不要跑出一份错的。**

### 3. 粒度原则：中间结果的粒度变化必须写明

明细 → 实体周期 → 实体，每一步粒度都在变。窗口计算（`rolling`、`shift`、`pct_change`）
**对粒度极其敏感**：在明细粒度上和实体周期粒度上算 `rolling`，结果完全不同，而且不会报错。

**做法**：计算流程表里单独一列写「输出粒度」。任何一个函数如果输入的粒度不确定，
先 `assert` 或先 `groupby` 到确定粒度。

典型错误：图省事在全表上直接 `rolling(3)`，**上一个实体的尾巴会接到下一个实体的头上**，
输出看起来完全正常。

### 4. 反向原则：每个主攻方向配一个反向指标

只奖励单一方向，行为一定会跑偏。

例（采购增量分析）：当前只奖励「量涨就谈」，可能诱导三种错误行为：

| 可能的跑偏 | 反向该看什么 | 数据是否具备 |
| --- | --- | --- |
| 为凑增长提前囤货 | 库存周转天数 | 未接入 |
| 量涨、单价也涨 | 同期单价变化率 | 具备 |
| 集中单一供应商换来降价 | 单一供应商占比 | 具备（未作硬约束） |

换到别的业务也一样：只考核「处理量」，会诱导抢单；只考核「满意度」，会诱导挑客户。

**做法**：每条主攻方向配一个反向指标，和主指标一起进报告，否则等于没有。
数据不具备时明确写「未接入」，**不要空着，也不要假装有**。

## 二、计算流程怎么写

每一步写清「输入什么、做了什么变换、输出什么粒度」。每步都要能直接翻译成函数。

| 步 | 输入 | 变换 | 输出粒度 |
| --- | --- | --- | --- |
| 1 | 明细 | 范围过滤、类型规范 | 明细 |
| 2 | 明细 | 按实体+周期汇总，补齐时间轴 | 实体周期 |
| 3 | 实体周期 | 逐实体 rolling 计算指标 | 实体周期 |
| 4 | 实体周期 | 取最后一期 + 分类判定 | 实体 |

第 3 步必须按实体分组算（`groupby(key).apply` 或 `groupby(key).transform`），
**不能在全表上直接 `rolling`**。

## 三、提取到分析层代码

| 要求 | 说明 |
| --- | --- |
| 一个分析一个模块 | 模块顶部 docstring 指向方案文档与 notebook |
| 阈值进模块级常量 | 并注明「改动请同步方案文档」 |
| 计算函数是纯函数 | 入参 DataFrame，出参 DataFrame，不读写文件 |
| 门面函数负责串流程 | 组装 `meta`，其余函数不碰 IO |
| 分类判定用纯函数 | 命中前一档即止，顺序不能随意换 |
| notebook 保留 | 用于下次复核，不要删已交付的 notebook |
