## 何时用
- 接入新数据源，要从 raw 设计出 processed 底表
- 新增一个分析，或改已有分析的口径与阈值
- 设计 notebook 的验证点，或把探索结论提取成代码
- 回答「为什么这个指标变了」的归因问题
- 判断一个结论能不能写进报告、能不能对外说

不适用时去哪：

| 场景 | 去哪 |
| --- | --- |
| 单纯取数 | 直接调项目取数门面函数；发现数据质量问题时，再走本 skill 第 4 步 |
| 纯排版、出报告文件 | 项目 reporting 层已封装；数字仍须来自分析层返回值，图表选型按 `references/06-交付.md` |
| 纯格式转换 | 直接转换，不留分析产物 |

## 〇、先判档：不是每个请求都走七步

| 档 | 什么请求 | 怎么走 |
| --- | --- | --- |
| 快答 | 单点取数、核对一个数、按已有口径查个数 | 直答。口径有歧义先问一句，拿到答复再算 |
| 常规分析 | 用已有口径回答一个问题、探索数据找信号 | 三问口头确认（不落表单）：① 谁拿结果做什么决定 ② 口径引用哪份已签署文档 ③ 还缺什么数据。确认后从第 5 步切入 |
| 完整分析 | 新指标、新口径、新阈值、接新源 | 走全七步，第 1–2 步走表单并签署 |

判档拿不准往高走一档。三档共同的底线：**先理解口径再计算，不从列名猜业务定义。**

## 一、完整分析的七步与产物

| 步 | 做什么 | 产物 |
| --- | --- | --- |
| 1 意图分析 | 想要什么结果、已知什么、数据拿不拿得到 | 意图确认书（已签署） |
| 2 口径定义 | 四件套 + 阈值理由 + 边界行为 | 口径确认表（已签署） |
| 3 取数 | 反推字段、定窗口、**多源对齐** | 实施方案「取数与关联」节 |
| 4 清洗 | 字段盘点、取值审计、口径差异、异常处置 | 八节来源文档 |
| 5 验证 | 先写验证点，再在 notebook 里试算 | notebook 契约头 + 验证记录 |
| 6 分析 | 计算流程、分类判定、反向检查 | 分析层计算模块 |
| 7 交付 | 图表选型、报告结构、口径披露 | 报告 + 规则说明 |

三份签署文档各管一段：意图确认书管「为什么做、数据够不够」，口径确认表管「怎么算」，实施方案只管「技术上怎么实现」。第 2 步没做完就进第 5 步，一定返工。

产物文档落在项目的文档区，**路径随项目约定，skill 不管目录名**。只要求三件事：
产物落盘、可追溯、互相引用（方案文档引用口径文档的哪一节，notebook 引用方案文档的哪一节）。

**完整分析内部分两条路径**。判断标准：这个源有没有已签署的来源文档和可复跑的清洗断言。有 → B，没有 → A。

- **路径 A · 接入新数据源**：走全七步，第 4 步产出八节来源文档。
- **路径 B · 用已有底表做新分析**：数据可得性直接引用来源文档，从第 2 步直入；第 3 步读 processed，第 4 步只复跑清洗断言，断言失败才回头修清洗。

## 二、五道门禁

| # | 门禁 |
| --- | --- |
| 1 | 口径不齐不取数 |
| 2 | 数据不完整不跑分析（缺周期报错，不补零） |
| 3 | 验证点没写不试算 |
| 4 | 验证点没过不进分析层 |
| 5 | 三处口径不一致不交付（方案文档、常量注释、报告规则说明同源） |

**宁可跑不出报告，不要跑出一份错的。** 每步还有自己的门禁细则，在对应 reference 的「门禁」节，走到哪步查哪份。

**返工回边**——走到后面发现问题，回到哪一步：

| 发现什么 | 回到哪 | 做什么 |
| --- | --- | --- |
| 第 3–4 步发现口径落不了地 | 第 2 步 | 改口径定义，重走签署 |
| 第 5 步验证点失败，是口径错 | 第 2 步 | 改口径、重签，再同步实施方案与 notebook |
| 第 5 步验证点失败，是计算错 | 原地 | 修计算，验证点不动 |
| 第 6 步发现关键数据缺失 | 第 1 步 2.2/2.3 | 重查可得性、走替代方案 |
| 口径争议挂起 | 挂起不阻断 | 金额或核心口径的挂起项，进下一步前必须清掉 |

## 三、五层边界

| 层 | 职责 | 铁律 |
| --- | --- | --- |
| raw | 来源文件的直接转换 | 不改列名、取值、单位，不补默认值；出错只能重导，修正都发生在 processed |
| processed | 清洗后底表 | 清洗是「让表可计算」，非业务加工；规则可复现，同一输入同一输出 |
| notebook | 探索、试错、核对、给业务方看 | 允许乱、允许删；结论未过验证点不进分析层代码 |
| analysis | 稳定的计算 | 纯函数，只吃 DataFrame 出 DataFrame；不做 IO，例外只有流程入口的门面函数 |
| reporting | 呈现 | 不算数，只排版；数字一律来自分析层返回值 |

补一条全局铁律：**代码与文档同源**——规则写不进文档的，就进不了代码；阈值全部进配置对象或模块级常量区。
