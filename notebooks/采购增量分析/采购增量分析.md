# 采购增量分析与谈判候选报表方案

## 一、背景与报表痛点

当前采购入库明细能够回答“买了什么、买了多少、向谁采购”，但不能直接回答“哪些物料的采购需求正在持续增长，以及哪些物料值得优先启动价格谈判”。业务人员仍需在大量明细中手工汇总和比较，主要存在以下问题：

1. 采购数据以明细形式分散，缺少物料级、月度级的统一趋势视图。
2. 单月采购量上升可能来自临时备货或偶发波动，仅看单月增量容易误判。
3. 低金额、近期断采物料与稳定增长物料混在一起，候选范围过大。
4. 缺少统一的增长指标和分级规则，不同人员筛选出的谈判对象不一致。
5. 核心供应商及其供货集中度需要额外统计，难以直接形成谈判对象清单。
6. 现有结果缺少明确优先级，业务无法快速区分“立即谈判、继续观察、暂不建议”。

因此，需要把采购入库明细转化为一套可重复执行的物料增量识别流程，形成结构化的谈判候选报表。

## 二、分析目标

本分析围绕“采购量增长是否真实、持续且具备谈判价值”建立筛选机制，目标包括：

- 将采购明细统一汇总到物料月度粒度，形成连续12个月的采购趋势数据。
- 同时衡量短期增长、中期趋势、增长连续性和近期需求集中度。
- 排除采购金额较低或最近3个月存在断采的物料，减少无效候选。
- 识别每个物料的核心供应商及单一供应商供货占比。
- 将物料划分为“优先谈判、观察、不建议”三档，并把无增长基线的新引入物料单列，形成可执行清单。
- 固化数据口径和分类规则，使报表可以按月重复运行和复核。

本分析不直接给出目标降价比例，也不代替业务对一次性备货、项目采购等特殊场景的人工判断。

## 三、数据源与分析范围

### 3.1 数据源与读取方式

当前来源为「采购入库」`procurement-inbound`。上游导出文件（Excel）由 `scripts/sync_data.py`
**原样**导入，按业务日期切成一天一个归档，路径为：

```text
data/raw/procurement-inbound/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet
```

raw 只追加 `_source`、`_fetched_at` 两列，不做字段改名和单位换算；清洗后的底表写入
`data/processed/procurement-inbound/<YYYY>/<YYYY-MM>/<YYYY-MM-DD>/data.parquet`。
读取时优先用底表，没有底表才退回 raw。

**一个参数代表当日/当月/当年，两个参数代表区间**，都是按记录里的「出入库日期」过滤：

| 写法 | 含义 |
| --- | --- |
| `read_inbound()` | 全部已归档数据 |
| `read_inbound("2026-09")` | 2026 年 9 月整月 |
| `read_inbound("2026-09-01", "2026-09-15")` | 9 月 1 日至 15 日 |
| `read_inbound("2025-10", "2026-09")` | 跨年 12 个月 |

目录日期即业务日期（已校验 60 万行零偏差），只用来挑候选文件；行级窗口仍以
`出入库日期` 为准，所以目录缺日不会把相邻日期的记录带进来。
每日一个归档、互不拼接，因此不存在「快照叠加」的问题。

完整约定见 [采购入库接入方案](../数据清洗/采购入库接入及清洗.md)；分析侧的字段名对齐见
`src/analysis/procurement_increment.py` 的 `normalize_columns`。

### 3.3 业务范围

板块和供应商范围共同构成分析范围。

**板块**仅保留以下三个，只用于源数据过滤，不进入最终汇总维度：

- 检验
- 检验产品
- 诊断

**供应商范围**只保留 `财务内部外供应商类型 = 外部单位` 的记录。关联单位（内部关联单位、外部关联单位）之间不是市场议价关系，纳入会同时扭曲增长排名和供应商集中度——实测关联单位占采购金额的 25%、数量的 69%，其中迪安诊断技术集团一家就占 14%。

被剔除的规模会写进运行摘要，不能无声消失：

| 供应商类型 | 行数 | 金额(万) | 占比 | 处理 |
| --- | --- | --- | --- | --- |
| 外部单位 | 419,357 | 149,389 | 72% | 保留 |
| 内部关联单位 | 167,645 | 52,725 | 25% | 剔除 |
| 外部关联单位 | 3,045 | 1,704 | 1% | 剔除 |
| 未标注 | 14,815 | 3,434 | 2% | 剔除 |

需要含关联交易复核时，用 `Config(external_only=False)` 跑一遍对比。

> 注意：源数据另有一列 `自定义内外部供应商（凯莱谱、生物为外部）`，它把内部供应商只算到 9,377 万（5%），与 `财务内部外供应商类型` 的 25% 差 5 倍。**本分析以 `财务内部外供应商类型` 为准**，另一列仅作参考，不要混用。

### 3.4 时间范围

**取数区间**和**分析窗口**是两个概念，不要混：

- 取数区间：`--start-date` / `--end-date`（写法和 `read_inbound` 一致），限定从归档里读哪一段；
- 分析窗口：结束月 `--end-month YYYY-MM`（不填取所读数据里的最大采购年月），
  起点由 `--window-months`（默认 12）向前推，含首尾两个月。

所以 `--start-date 2025-10-01 --end-date 2026-09-30` 就是「读这一年，分析窗口 2025-10 ~ 2026-09」；
只给 `--end-month 2026-06` 时，取数区间仍是全部归档，窗口是 2025-07 ~ 2026-06。

当前代码不会额外判断结束月是否已经完整结束（例如当月只过了半个月也算一个月）。

**回溯受数据覆盖范围约束**：脚本在分析前校验分析窗口内的 12 个月是否都有数据。若窗口内存在缺失月份（数据覆盖不足），脚本会直接报错中止，而不是用 0 采购补齐——补齐会让「最近 3 个月采购量占比」虚高，把本该「不建议」的物料误判为「观察」。需要回溯更早时点，须先取到覆盖该区间的数据。

### 3.5 采购量和金额口径

- **采购量**：直接汇总带符号的「数量」。退货记录为负数，会在汇总时冲减采购入库数量（全量约 −71,472 件，占 0.14%）。
- **采购金额**：汇总「采购不含税金额(万)」，同样含红字冲减（全量约 −1,552 万元，占 0.75%）。
- **月加权平均价(元)**：月采购不含税金额(万)×10000 / 月采购量；月采购量为 0 时为空。只有一列，单位是元/件、元/支等，不要和「万元」混算。

**有数量无金额的记录（占 11.4% 行、19.2% 数量）**：主要是随试剂配套的免费耗材（吸管、反应杯、采样拭子、细胞保存液）和内部免费供货。处理方式：

- 数量**照算**（实物消耗量真实发生），金额按 0 计；
- 因此「数量涨」不等于「采购额涨」，也不必然可以谈判。清洗液、反应杯这类物料的免费量占比可达 99%；
- 加权平均价会被这类记录稀释（1,079 个物料受影响，个别低估 100%），均价列仅作参考，不作为筛选依据；
- 判断一个候选是否值得谈，看它的**最近12个月累计采购金额**和免费比例是否异常，不要只看趋势指数。

**盘盈入库** 53 行金额全为 0，对金额无贡献，保留在数量里。

## 四、识别流程

```mermaid
flowchart LR
    A[采购入库明细] --> B[板块与供应商范围过滤]
    B --> C[12个月窗口与字段清洗]
    C --> D[最近6个月金额过滤]
    D --> E[物料月度汇总与月份补齐]
    E --> F[增长指标与供应商指标计算]
    F --> G[最近3个月零采购过滤]
    G --> H[四档分类与排序]
    H --> I[Excel报告、月度数据、规则说明与图表]
```

### 4.1 范围过滤与数据清洗

1. 过滤"检验、检验产品、诊断"三个目标板块。
2. 过滤 `财务内部外供应商类型 ≠ 外部单位` 的记录，剔除行数和金额记入运行摘要。
3. 将源数据中存在的年份、月份、物料编码、数量、采购金额和采购单价转换为数值类型。
4. 删除年份、月份、物料编码或数量为空的记录。
5. 根据最大采购年月确定12个月分析窗口，并校验窗口内每个月都有数据。

### 4.2 金额过滤

月度汇总前，仅保留最近6个月累计采购不含税金额**大于5万元**的物料。

该过滤用于排除采购价值较低、暂不具备明显谈判价值的物料。金额等于5万元时不进入分析。

### 4.3 月份补齐与月度汇总

以“物料编码+年月”为月度汇总粒度：

- 月采购量为数量合计之和。
- 月采购不含税金额为采购不含税金额之和。
- 每个物料补齐分析窗口内的12个月；无采购记录的月份数量和金额填0。
- 月采购量为0时标记为零采购月份。
- 同一物料的名称、规格、品牌和分类等固定属性，在金额过滤后按时间排序并取首个非空值。

月份补齐用于区分“没有采购记录”和“持续采购”，避免缺失月份被误认为趋势连续。

### 4.4 增长指标计算

每个物料按年月排序后计算4个核心指标：

| 指标 | 计算方式 | 作用 |
| --- | --- | --- |
| 最近1个月环比增长率 | (本月采购量-上月采购量)/上月采购量 | 判断最新一个月是否仍在增长 |
| 采购量趋势指数 | 最近3个月平均采购量/前3个月平均采购量-1 | 判断近期采购量是否整体上台阶 |
| 连续增长月数 | 截至当前月连续环比为正的月份数 | 判断增长是否连续 |
| 最近3个月采购量占比 | 最近3个月采购总量/最近12个月采购总量 | 判断需求是否集中在近期释放 |

环比仅在上月采购量大于0时计算。本月采购量为0且上月大于0时，环比为-100%；上月采购量为0时，环比为空并中断连续增长。

**基期为 0 时趋势指数必须留空，不能写成 inf或负数。** 前3个月平均采购量 ≤ 0 有两种来源：新上量物料，以及前3个月净退货的物料。这两种都没有可比的增长基线：

- 写成 `inf`：既满足「≥20%」的优先谈判门槛，降序排序又永远排第一，会把新品顶到谈判榜首；
- 写成负值（基期为负时除出来）：会得到一个看起来像「暴跌」的假指标。

因此代码用 `baseline.where(baseline > 0)` 把这类记录的指数置空，并在分类阶段单列成「新引入」档，见第五节。

**基期极小时指数会被放大**：本期 514 个优先谈判物料里有 8 个前3个月平均采购量不足 1 件，趋势指数上到 9~55 倍。这类记录是真实的量级跳升，不是算错，但要连同「前3个月平均采购量」一起看，只看百分比会被误导。

### 4.5 供应商指标计算

在当前12个月分析窗口内，按“物料编码+供应商名称”汇总采购不含税金额：

- 核心供应商：该物料累计采购不含税金额最高的供应商。
- 单一供应商供货占比：核心供应商金额/该物料12个月累计采购不含税金额。

供应商占比用于辅助人工判断供应集中度，当前不参与自动优先级分类。

### 4.6 零采购过滤

指标计算完成后，删除最近3个月存在零采购月份的物料。只有最近3个月持续有采购记录的物料才进入谈判优先级分类。

“最近3个月零采购月份”作为内部过滤指标保留，但目标报告不再输出该字段，因为所有进入报告的物料该值均为0。

## 五、谈判优先级分类

分类按"新引入 → 优先谈判 → 观察 → 不建议"的顺序执行。物料命中前一档后不再进入后续判断。

| 优先级 | 代码判定规则 | 业务含义 |
| --- | --- | --- |
| 新引入 | 前3个月平均采购量 ≤ 0（无增长基线），且最近3个月有持续采购 | 新上量或前期净退货，需求本身可能真实增长，但不属于「采购量增长」，单列供业务判断 |
| 优先谈判 | 有基期，且采购量趋势指数≥20%，并且最近1个月环比增长率≥10%或连续增长月数≥2 | 采购量已经明显提升，且短期增长仍在延续，可优先核实并启动谈判 |
| 观察 | 未达到优先谈判，且采购量趋势指数≥10%或最近3个月采购量占比≥30% | 已出现增长或近期需求集中，但增长强度、连续性尚不足 |
| 不建议 | 既不满足优先谈判，也不满足观察 | 当前增长信号不足，暂不建议因采购增量启动谈判 |

**新引入不占谈判名额**：它不进「优先谈判」计数，也不参与增长排名（趋势指数为空），只在报告末尾单列一档供业务确认。

最近3个月无零采购月份属于进入分类前的统一准入条件（在 `build_report` 里已过滤），分类函数内不再重复判断。

分类完成后，按照以下顺序排序：

1. 谈判优先级：优先谈判、观察、不建议、新引入。
2. 同一优先级内，采购量趋势指数降序。
3. 趋势指数为空（仅新引入）或相同时，最近12个月累计采购不含税金额降序，再按最近3个月采购量占比降序。

### 6.1 报告工作表

报告工作表用于业务筛选和谈判准备，目标输出字段如下：

| 字段类别 | 字段 |
| --- | --- |
| 物料信息 | 物料编码、物料名称、规格、品牌、五级分类 |
| 供应商信息 | 核心供应商名称、单一供应商供货占比 |
| 规模指标 | 最近3个月平均采购量、前3个月平均采购量、最近12个月累计采购不含税金额(万) |
| 增长指标 | 采购量趋势指数、最近1个月环比增长率、连续增长月数、最近3个月采购量占比 |
| 分类结果 | 谈判优先级 |

最近3个月零采购月份只作为分类前的准入过滤条件，不作为最终报告字段。进入报告的物料该值均为0，保留会造成无效信息。

新引入物料的趋势指数为空，报告里显示为空白单元格；它的「前3个月平均采购量」为 0 或负值，可以据此识别。

### 6.2 月度数据工作表

月度数据工作表保留每个物料12个月的完整时间序列、固定属性、月采购量、月采购金额、加权平均价和各项滚动指标，用于复核最终分类结果。

均价只有一列 `月加权平均价(元)`，单位是元/件。此前版本同时输出了 `月加权平均价`（万元/件）和 `月加权平均价(元)` 两列，单位不同、名字相近，已删除前者。

### 6.3 规则说明工作表

规则说明工作表用于解释报表口径和分级结果，供业务人员直接查看，无需阅读Notebook代码。内容包括：

- 报表用途、分析范围（含板块和供应商范围）和12个月分析窗口。
- 最近6个月金额门槛和最近3个月连续采购准入条件。
- 采购量与金额口径：退货冲减、有数量无金额的免费供货如何处理。
- 新引入、优先谈判、观察、不建议四档规则与对应业务动作。
- 最近1个月环比增长率、采购量趋势指数（基期为 0 时留空）、连续增长月数和最近3个月采购量占比的定义。
- 使用边界：报表不替代对一次性备货、项目采购、价格、替代供应商和质量表现的业务判断。

### 6.4 图表工作表

图表工作表只保留支持采购决策的两张图，不使用点位密集、难以定位具体物料的气泡图：

| 图表 | 分析角度 | 业务用途 |
| --- | --- | --- |
| 各优先级覆盖采购金额 | 对比优先谈判、观察、不建议、新引入四档物料的最近12个月采购金额 | 判断各档候选覆盖的采购规模，明确优先谈判的总体价值 |
| 优先谈判物料 Top 15 | 按最近12个月采购金额，对优先谈判物料进行横向排名 | 快速锁定金额最高的候选物料，优先核实需求原因并准备谈判 |

图表页顶部同时展示优先谈判候选数和对应采购金额；右侧保留四档优先级汇总与Top 15物料、核心供应商、采购金额明细，确保图表结论可追溯。

### 6.5 运行摘要工作表

第一张表，用于判断这轮数据能不能用：

- 分析窗口、板块范围、**供应商范围与因范围剔除的行数/金额**；
- 金额准入门槛、过滤后明细行数、覆盖物料数、报告物料数；
- 四档各自的物料数与优先谈判覆盖金额；
- 数据来源、归档日、覆盖月份、数据文件路径。

## 七、业务使用方式

### 7.1 优先谈判

业务先核实物料增长是否来自正常、可持续需求，再结合核心供应商和供货占比准备谈判。重点确认是否存在一次性备货、新项目集中采购或临时缺货补库等特殊原因。

同时看两个警示信号：**基期采购量是否极小**（前3个月平均不足1件时趋势指数会被放大）、**免费数量占比是否过高**（超过 50% 说明量增主要来自配套赠送，谈判空间有限）。

### 7.2 观察

观察类物料暂不直接启动谈判，按月更新数据，重点跟踪趋势指数、最近1个月环比和连续增长月数是否进一步增强。

### 7.3 不建议

不建议类物料保留在报告中用于完整复核，但不作为当前采购增量谈判的重点对象。

### 7.4 新引入

新引入物料不占谈判名额，但常是新品上量或新供应商导入的第一批信号，建议单独交业务确认：是真实的新增需求，还是一次性试用/备货。确认后再纳入下一轮的谈判或观察。

本报表提供的是采购增量证据和优先级，不等同于最终谈判结论。实际谈判还应结合市场价格、替代供应商、合同周期、质量表现和业务需求稳定性进行判断。

## 八、最终目标与预期价值

最终目标是建立一套按月运行、口径统一、结果可复核的采购增量识别机制，把“人工从明细中寻找增长物料”转变为“系统化生成谈判候选清单”。

预期价值包括：

- 缩小人工分析范围，优先关注高金额且持续采购的物料。
- 用统一指标替代主观判断，提高不同人员筛选结果的一致性。
- 同时提供增长趋势、采购规模和核心供应商信息，增强谈判准备的证据基础。
- 保留月度明细和指标计算结果，使每个优先级都可以追溯和复核。
- 形成固定月报，为后续接入自动化任务、数据库和采购工作台提供标准口径。
