# 采购降本自动化核算方案

**当前步骤：第一步——业务理解与指标构建（进行中）**

2026-11-02 开始按场景分析流程梳理。以下既有方案作为业务讨论的起点；目标、现行核对方式、指标和字段清单仍需逐项核实，原文列出的待确认事项继续保留。采购入库的共享来源规则见 [采购入库接入及清洗](../数据清洗/采购入库接入及清洗.md)，实际用于本场景的字段、数据覆盖和版本将在数据源步骤核对。

## 一、业务理解与指标构建

### 1.1 业务目标

每月向管理层汇报已实现降本、帮助采购员核对自己的降本，并结合个人年度目标考核采购绩效。月报支持按采购主体、负责人、五级分类、供应商和核算类型查看新增、存量及合计；采购员核对逐笔明细。税率调整和返利独立展示，不计入总降本。

### 1.2 当前痛点

用户原话：“工作量大，然后很多需要人为来补充填写。”同供应商、同物料编码的直接涨跌由系统处理；渠道、品牌和规格替换由业务补充基础信息、系统计算，无法判断的关系由采购员复核。

### 1.3 现行参考

目前“一位采购员用 Excel 具体核算”；采购员以**物料－供应商－单价**聚合并判断协议与入库的对应关系。现行 Excel 是后续核验结果的参考，尚未取得用于对账的数据行；返利原表表头见 2.4。SRM 协议版本与实际入库是直接涨跌的数据依据，来源字段与覆盖待核实。

### 1.4 指标

| 指标 | 定义及公式 | 常用维度 / 周期 |
|---|---|---|
| 各类型降本 | 直接降价、渠道替换、品牌替换、规格替换分别按 4、5 节计算；直接上涨不计入，替换成本增加不计入并待复核 | 主体、负责人、五级分类、供应商、物料、类型；月、年 |
| 新增 / 存量降本 | 按单条事项的核算开始年度区分，具体见 3.2 | 同上；月、年 |
| 总降本 | 四类降本合计；不含税率调整和返利 | 同上；月、年 |
| 个人年度目标完成率 | 已复核的个人年度累计降本（新增＋存量）÷个人年度降本目标；目标未填时显示“目标待填写”，为零时待确认 | 采购员、年度；月报展示截至当月累计 |

计算采用含税价格；价格、换算和金额精度及展示单位待确认。每条计算明细的粒度、空值和无业务月份的展示方式在数据验证时确认。税率仅独立展示，不作为降本计算输入。

| 用途 | 所需信息 |

| 入库匹配 | 可追溯的入库记录、采购主体、供应商、物料、实际含税单价、带符号数量及单位、入库日期、五级分类 |

### 1.6 核算范围

基于 SRM 采购价格协议明细的全部版本、ERP采购入库流水及业务填报信息，建立自动化采购降本核算流程，实现数据获取、价格匹配、降本计算、业务复核、标准化处理与统一汇总。

第一阶段分为两条计算路径：

| 核算类型 | 处理方式 | 是否计入总降本 |
|---|---|---|
| 直接涨跌 | 根据 SRM 采购价格协议明细的版本记录与采购入库流水对应计算；直接上涨本身不计入降本 | 符合口径的降价计入 |
| 渠道替换 | 人工填报基础信息，系统计算 | 是 |
| 品牌替换 | 人工填报基础信息及单位换算关系，系统计算 | 是 |
| 规格替换 | 人工填报基础信息及单位换算关系，系统计算 | 是 |
| 税率调整 | 从协议版本生成独立表，仅展示税率发生变化的记录，供采购员查看 | 否，仅展示 |
| 返利 | 独立表格人工填报 | 否，仅展示 |

**年度总降本 = 直接涨跌 + 渠道替换 + 品牌替换 + 规格替换**

各类型降本再根据核算年度分别归集为新增和存量。

## 二、数据来源与处理职责

### 2.1 ERP入库数据

ERP入库流水中与本场景有关的业务信息包括：

| 字段 | 作用 |
|---|---|
| 采购主体 | 确定降本适用公司 |
| 供应商 | 匹配采购关系 |
| 物料 | 匹配采购物料 |
| 单价 | 实际入库含税单价 |

| 日期 | 判断核算周期及月份 |

ERP单价与协议调价记录中的价格按含税口径核算，实际字段需核对。

共享入库底表已有采购信息，来源及清洗规则见[采购入库接入及清洗](../数据清洗/采购入库接入及清洗.md)。目前底表保留取数时间但未保留原始「单据编码」；单据编码能否唯一定位入库行及如何关联清洗明细待核实，不能仅凭重复记录自动去重。底表中的供应商名称与 SRM 供应商编码如何对应、缺档日是否确无业务以及重复行处置均待核对。

**来源预查（2026-11-03，只读，尚非业务覆盖确认）**：采购入库原始层和清洗层均有 631,990 行，业务日期范围为 2025-01-01 至 2026-10-31，涉及 621 个有记录的业务日期。2026 年 10 月清洗层有 27,128 行、28 个日档；10 月 2、3、4 日没有日档，不能直接认定为无业务。读取接口核对到该月清洗层的已知原始输入版本一致、无已知原始日档缺失；上游业务覆盖仍未核实。现有明细可提供物料编码、供应商名称、含税单价、数量、日期、采购主体、主单位及五级分类；原始层和清洗层均未见供应商编码，清洗层未保留原始单据编码。跨系统对应及逐笔溯源需进一步核对，不能据此认定已具备正式核算条件。

### 2.4 税率调整与返利

税率从协议版本生成独立展示表，仅展示前后税率发生变化的记录，提供采购员查看，不要求采购员手工填写税率（用户确认，2026-11-03）。税率与降本统一使用 4.2 的版本分流和前序协议查找规则，比较对应明细的前后税率；找不到可确认的前序税率时不能推定发生变化，未匹配记录如何反馈待确认。返利通过独立表反馈，遵循最小字段原则。

税率变化表字段初稿：供应商编码、供应商名称、物料编码、产品名称、规格；旧协议编号、旧版本号、原税率、旧价格生效和失效日期；新协议编号、新版本号、新税率、新价格生效和失效日期。管理组织、采购模式随协议明细保留供核对。用户要求新旧协议号信息完整，便于追溯；实际字段可得性和最终展示方式待核对，不要求采购员重复填报。

返利表第一阶段字段范围（用户确认，2026-11-03）：采购组织、供应商、物料、五级分类、执行日期、返利比例、返利条款。暂不增加“影响金额”“业务依据”，也不把原表中的“返利额”列入当前字段范围；后续如有实际需要再确认，不以表头推断返利公式。

返利原表目前人工填写，用户提供的表头（尚无数据行）：库存组织、责任人、入库月份、供应商、执行日期、分类、物料、说明、品牌、货号、规格、单位、税率、子公司采购单价（元）、入库数量、子公司采购金额（元）、有效数据、原价格（元）、现价格（元）、有效数据取入库数量、返利比例、返利额（万元）、匹配列、核算备注、是否新增、入库序号、提供时间。该清单仅供核对，不代表新表需全部保留。

第一阶段仅进行基础字段校验、数据归集与展示，不纳入总降本，也不开发自动协议返利核算。

## 三、统一核算周期与归属规则

### 3.1 核算周期

直接涨跌及三类替换涨跌统一使用价格生效日期推算核算周期。

月度汇总及归档按自然月，次月初拉取完整上月数据后归档；与每条明细独立的核算周期分别定义（用户确认，2026-11-02）。

**每条降本明细独立核算连续12个自然月。**

| 价格生效日期 | 核算开始 | 核算结束 |
|---|---|---|
| 2026-03-01 | 2026-03-01 | 2027-02-28 |
| 2026-06-15 | 2026-07-01 | 2027-06-30 |
| 2026-10-16 | 2026-11-01 | 2027-10-31 |
| 2026-12-20 | 2027-01-01 | 2027-12-31 |

规则：价格生效日为当月1日，从当月1日起算；其他日期从次月1日起算。到期后，该明细停止核算。

即使期间再次调整价格，前次明细的周期也不重启。

### 3.2 新增与存量

最终只保留两个汇总维度。

| 维度 | 核算口径 |
|---|---|
| 新增 | 调价或替换开始核算的当年度产生的降本贡献 |
| 存量 | 跨自然年度后、原12个月周期内继续产生的降本贡献 |

同自然年度连续调价，各次贡献均计新增。次年1月1日起，仍在有效期内的贡献转为存量。

原业务使用的“滚动存量”主要体现连续调价后前次贡献的延续计算，不再设立独立的第三个汇总维度。

说明：以**核算开始年度**作为新增认定年度；价格生效日期在年末、核算从次年1月开始时，次年的贡献归为新增。此边界已由用户于2026-11-02确认。

### 3.3 负责人、目标及月度复核

每笔降本对应一位负责人。先沿用[采购增量派发负责人规则](../../src/dispatch_rules.py)中已匹配的五级分类与人员关系生成初稿；分类未匹配、或同一物料分类多值导致负责人无法确定时标记为“待确认”，由业务复核指定，不使用派发任务默认指派的兜底规则。负责人可人工修正；人员按整月交接，之前已确认的降本保留原负责人，新负责人负责变更后的降本。

个人年度降本目标在多维表填写，按采购员和年度关联；完成率公式见 1.4。完成率作为独立指标，年度目标调整后可重新计算完成率，不改变历史降本核算结果（用户确认，2026-11-03）。次月初拉取完整上月数据，生成并归档待复核初稿，采购员通过多维表确认或修正后形成正式结果，用于管理汇报和绩效考核。最终发布责任、权限和版本留痕方式待设计。

### 3.4 退货及结账

退货对应的降本在退货当月冲减。例如 3 月核算降本 1,000 元，4 月退回其中 200 元对应的数量，3 月保持 1,000 元，4 月冲减 200 元。红冲按流水记录的业务日期和数量正负参与对应月份的核算：匹配到有效降本事项的负数量冲减当月贡献；若另有更正后的正向记录，按其业务日期和匹配条件分别计算（用户确认，2026-11-03）。核算期结束后的退货及红冲等边界先保留待定，出现时结合实际明细核对处理，不预设额外的常规流程。

用户说明：次月时上月入库数据已结账，正常情况下不会在次月补录上月漏记的入库；暂不设计常规补录流程。业务入库结账与降本初稿后续复核是两个环节。

## 四、直接涨跌自动核算

### 4.1 核算公式

**单位降本 = 本次原含税价－本次现含税价**

**降本金额 = 单位降本 × 符合条件的实际入库数量**

每次调价通常只计算自身产生的固定增量价差；基础公式由用户于2026-11-02确认。

直接价格上涨本身不计入降本统计，不以该次上涨的负向金额冲减总降本；原始价格记录仍需保留。降价后价格回升须由采购员确认价格性质：例如 100→90 后按 95 入库，若确认是适用该入库的正式涨价且前次降价仍在有效期内，前次贡献按每件 5 元计算，上涨不另列负向降本。若为临时价格，该笔如何核算由采购员确认，确认前不纳入正式汇总。多次调价或多条有效贡献交织时先人工复核，不自动推广此示例。

### 4.2 入库匹配逻辑

系统按以下顺序处理：

1. 按下方版本分流规则寻找价格的前序明细，识别可确认的调价历史；关系不明交采购员复核。
2. 以现行业务的“物料－供应商－单价”作为入库聚合及协议对应的业务键；适用组织不加入该键。入库日期和实际采购主体仍保留，用于按月及按主体汇总和下钻，不能将不同月份或主体的信息丢失。同供应商同物料可能有多份协议和多个价格，实际字段、价格口径及键的唯一性待以数据验证。
3. 对确认关系的本次及同一调价历史中的后续执行价格，匹配有效周期内的入库，分别计算贡献；价格回升按 4.1 的例外处理。

当协议、入库或连续调价的对应关系不唯一时，交由采购员复核；具体需要哪些字段和匹配顺序须用实际数据确认。

不能简单使用“入库价低于调整后价格”作为匹配依据，因为不同采购主体或独立采购价格可能同时存在。

**前序版本及跨协议延续（用户确认，2026-11-03）**：当前协议非 V1 时，先查找本协议上一版本的对应物料明细；当前协议为 V1 时，前序明细如存在则跨协议查找，对每份旧协议先取其最后一个版本，再查找对应物料明细并判断连续性，不将同一旧协议的多个版本当作多个上游候选。结合管理组织、采购模式、供应商判断上游唯一性，并比较前一价格失效与新价格生效日期：两段有效期重叠，或存在小于一年的间隔时，满足时间条件；间隔一年或更久不算连续。适用组织不作为前序协议连续性判断条件，也不按其拆分前序关系。其他条件匹配且上游唯一时认定连续；按时间存在多个候选旧协议时交采购员复核，不能仅按时间最近或价格高低选定。若认定新协议是旧协议的延续，则比较旧协议最后有效价格和新协议生效价格；新价格降低形成新的降价贡献，原降价贡献在其自身 12 个月内按已确认规则继续核算，新贡献另按自身生效日期计算 12 个月，间隔不重启或延长原周期。价格不变不新增贡献；价格回升按已确认例外复核。

“一年”按日历年对日计算，不固定按 365 天（用户确认，2026-11-03）。例如旧价格 2025-06-30 失效，新价格 2026-06-29 生效，小于一年；2026-06-30 生效则恰好一年，不连续。价格失效日期当天仍有效，例如 6 月 30 日失效，6 月 30 日仍有效、7 月 1 日起失效（用户确认，2026-11-03）。旧价格失效日为 2 月 29 日、次年无对应日期时的具体边界待确认。

**协议 V2 新增物料（用户确认，2026-11-03）**：物料在本协议 V2 才新增、V1 没有该物料时，从其他协议查找该物料的前序明细，按上述上游唯一性和时间条件判断；找不到可确认的前序时不推算原价，标记待核实。若物料曾在本协议更早版本出现、上一版本缺失后再次出现，如何查找前序仍待单独确认。

示例：协议 A 原价 100，2026-02-01 降至 90，前次贡献每单位 10，核算至 2027-01-31；协议 B 已按上述规则认定延续 A，并于 2026-07-01 执行 80，则 B 新增贡献每单位 10，核算至 2027-06-30。

| 入库月份 | 按 80 元入库 100 件的降本 | 归属 |
|---|---|---|
| 2026 年 8 月 | A：1,000 元；B：1,000 元，合计 2,000 元 | 均为新增 |
| 2027 年 1 月 | A：1,000 元；B：1,000 元，合计 2,000 元 | 均为存量 |
| 2027 年 2 月 | A 已到期；B：1,000 元 | 存量 |

同一笔入库可以支持多条尚未到期的调价明细，但每条明细只计算自己的增量价差。

## 五、替换涨跌计算

### 5.1 渠道替换

渠道替换采用相同物料编码，新旧供应商可不同，无需进行单位换算。

**降本金额 =（原渠道含税价－新渠道含税价）× 新渠道ERP入库数量**

采购员确认新旧供应商关系、价格生效日期及适用主体；系统按照新供应商、新物料、实际执行价格和有效周期匹配入库。

上述渠道替换口径由用户于2026-11-02确认。

### 5.2 品牌替换及规格替换

由采购员确认新旧物料关系与换算系数。

换算系数统一定义为：

**每个ERP采购计量单位对应的标准可比单位数量。**

计算公式：

原可比单位价 = 原含税单价 ÷ 原换算系数

新可比单位价 = 现含税单价 ÷ 新换算系数

实际可比数量 = ERP入库数量 × 新换算系数

**降本金额 =（原可比单位价－新可比单位价）× 实际可比数量**

例如：

| 项目 | 原品牌 | 新品牌 |
|---|---|---|
| 含税单价 | 100元/盒 | 45元/盒 |
| 规格 | 100测试/盒 | 50测试/盒 |
| 可比单位价 | 1元/测试 | 0.9元/测试 |

假设新品牌入库200盒：

实际数量 = 200 × 50 = 10,000测试

降本金额 = (1－0.9) × 10,000 = **1,000元**

品牌与规格替换的换算关系属于业务判断内容，必须经过人工复核，不能仅根据包装名称自动推断。

上述品牌及规格替换的换算计算口径由用户于2026-11-02确认。

替换后可比成本增加的事项不计入降本，也不冲减总降本；用户说明此类记录一般是填错，出现时标记为待采购员复核。

### 5.3 替换后再次直接降价

**已确认：替换降本与后续直接降价可以同时延续核算。**

例如先发生渠道替换，再发生直接降价：

| 明细 | 价格变化 | 单位贡献 |
|---|---|---:|
| R001 渠道替换 | 供应商甲100→供应商乙90 | 10元 |
| T002 直接降价 | 供应商乙90→80 | 10元 |

假设供应商乙按80元入库100件，且两条明细均在有效的12个月周期内：

| 降本来源 | 金额 |
|---|---:|
| R001替换降本 | 1,000元 |
| T002直接降本 | 1,000元 |
| 合计 | 2,000元 |

原替换降本继续按固定的10元差额计算，后续直接降价也只计算新增的10元差额。

品牌、规格替换后，如发生直接降价，也遵循固定贡献原则。替换部分使用可比单位计算，后续直接涨跌使用对应新物料的采购计价单位计算。

系统需要通过采购员确认的替换关系，将新供应商、新物料后续形成的调价明细连接起来。

## 六、人工复核与数据标准化

### 6.1 复核职责

| 环节 | 责任方 | 核心内容 |
|---|---|---|
| 基础信息填报 | 采购员 | 新旧关系、价格、单位、换算系数、生效日期 |
| 入库信息核对 | 脚本 / 采购员 | 按物料、供应商、单价聚合及匹配，并保留入库日期和实际采购主体供汇总核对 |
| 调价关系识别 | 脚本 | 自动识别历史调价及后续价格 |
| 歧义关系确认 | 采购员 | 确认无法唯一匹配的关系 |
| 数据标准化 | 脚本 | 统一字段、含税价格、可比单位、月份 |
| 金额核算与校验 | 脚本 | ERP数量匹配、公式计算、重复检查 |
| 结果确认 | 采购员 / 正式发布责任人待确认 | 采购员复核或修正初稿后形成正式结果；最终发布责任待明确 |

### 6.2 程序校验

第一阶段重点执行以下校验：

| 校验项 | 具体要求 |
|---|---|
| 基础字段 | 价格、数量、日期及业务关系完整有效 |
| 主体归集 | 按实际入库主体归集；适用组织不加入物料－供应商－单价业务聚合键 |
| 单位换算 | 原、新可比单位一致，系数有效 |
| 调价关系 | 连续调价前后价格衔接正确 |
| 周期 | 入库日期在对应明细的有效12个月内 |
| 重复核算 | 同一入库记录对同一降本明细不得重复计算 |
| 归因 | 同一段价差不得同时被直接涨跌和替换涨跌重复归集 |

同一入库记录参与不同降本明细的有效增量贡献属于正常情况，不应被简单认定为重复数据。

### 6.3 异常处理

第一阶段只需要保留简洁的异常机制。

| 异常 | 处理办法 |
|---|---|
| 入库主体信息异常 | 标记待核对，保证按实际主体汇总的数据可追溯 |
| 调价历史存在歧义 | 交采购员复核关系 |
| 入库价格无法关联 | 输出待核对明细 |
| 单位换算缺失或异常 | 暂不计算对应替换明细 |
| 计算结果与业务依据冲突 | 标记异常，修正后重新计算 |

没有异常的数据正常计算；存在异常的部分单独列示，不阻断其他已确认记录。

## 九、尚未最终确认的业务边界

以下事项保留为待确认或待用真实数据验证，不影响已经确认的规则。

| 优先级 | 问题 | 建议处理 |
|---|---|---|
| 高 | 前序查找时间边界 | 失效日为 2 月 29 日时次年对应日期如何确定，需核对；失效当天仍有效、一年按日历年对日计算、有效期重叠满足时间条件、间隔恰好一年及以上不连续已确认 |
| 高 | 前序及入库关系 | V1 无前序是确无历史还是数据缺失；物料在本协议更早版本出现、上一版本缺失后再次出现如何处理；多版本号跳号，以及供应商编码如何对应入库名称，需用数据核实。前序查找对应同一物料，V2 才新增的物料跨协议查找，适用组织不参与前序连续性判断，多候选旧协议按已确认规则复核 |
| 高 | 入库逐笔溯源及防重 | 原始单据编码能否唯一定位清洗后的入库行、是否需要补充共享底表字段或其他可靠标识待核实；已知重复行处置和缺档日覆盖仍未确认 |
| 高 | 退货及价格例外 | 核算期结束后的退货和红冲等边界先保留待定，出现时结合实际明细核对；临时价格、多条有效贡献交织及其他异常更正需确认；上月入库正常不会次月补录，核算期内的红冲按流水日期和数量正负处理已确认 |
| 中 | 税率和返利独立表 | 税率变化表字段可得性及无法确认前序税率时如何反馈；返利表按已确认的第一阶段字段范围准备，后续如需增加字段再确认，不推定自动返利公式 |
| 中 | 来源覆盖及数量单位 | SRM 全版本、生效价格和日期的覆盖，次月初数据完整性，协议计价单位与入库单位的一致性，以及多单位、零价和赠品如何处理 |

## 十、第一阶段验收要求

重点验证以下典型业务场景：

| 测试场景 | 预期结果 |

| 单次直接降价 | 准确匹配主体、价格、日期及实际数量 |
| 同年度连续降价 | 前后调整分别计算固定差额，均归新增 |
| 同协议前序版本 | 非 V1 查本协议上一版本；前序缺失时不凭空补价 |
| V2 新增物料 | V1 无该物料时跨协议查找前序，找不到可确认前序不推算原价 |
| 跨协议延续 | V1 查其他协议并先取各旧协议最后版本；满足时间条件的上游唯一时认定连续，多候选旧协议复核 |
| 跨协议时间边界 | 失效当天仍有效；有效期重叠满足时间条件；一年按日历年对日，恰好一年或以上不连续；2 月 29 日的边界按确认后规则验证 |
| 跨年度延续 | 未到期贡献在次年归存量 |
| 多采购主体 | 业务键按物料、供应商、单价聚合；保留并按实际入库主体归集 |
| 渠道替换 | 按新供应商、新物料实际入库计算 |
| 品牌、规格替换 | 按人工确认的换算关系计算可比数量 |
| 替换后再次降价 | 替换贡献与直接降价贡献分别延续，不重复计算价差 |
| 异常或未复核数据 | 不进入正式汇总，保留异常明细 |
| 降价后价格回升 | 采购员先确认正式或临时价格；正式上涨单次示例按 4.1 复核 |
| 月度退货 | 在退货当月冲减；核算期结束后的退货待定 |
| 月度红冲 | 按流水业务日期及数量正负影响对应月份；超期边界待核实 |
| 负责人交接 / 年度目标 | 整月交接不改写此前已确认归属；目标未填显示“目标待填写”；目标调整后可独立重算完成率，不改变历史降本结果 |
| 税率调整、返利 | 税率表按与降本统一的前序规则比较，仅展示发生变化的记录；二者独立展示且不影响总降本 |

**第一阶段验收目标：核算结果可计算、可复核、可追溯，并能通过ERP入库数据和业务填报依据复现。**
